# مصفوفة الصلاحيات

> جدول مرجعي كامل: ماذا يستطيع كل دور فعله في كل وحدة، مع شرح صلاحية «مستنداتي فقط» وصلاحيات التقارير والإعدادات والوكيل الذكي.

## نظرة عامة

النظام يتبع نموذج RBAC (التحكم بالوصول حسب الدور): كل عملية حساسة تُفحص ضد صلاحية نصية مثل `sales.create` أو `accounting.post`. صيغة الصلاحية: `الوحدة.الإجراء`.

الإجراءات الثمانية لكل وحدة:

| الإجراء | المعنى |
|---|---|
| `view` | عرض الوحدة وقوائمها وتقاريرها |
| `own` | تقييد العرض والتحرير على **مستنداتي فقط** (انظر القسم الأخير) |
| `create` | إضافة مستندات أو سجلات جديدة |
| `edit` | تعديل الموجود (بما فيها تعديل المسودات) |
| `delete` | الحذف — عملياً للمسودات فقط، فالمُرحّل لا يُحذف |
| `post` | الترحيل: اعتماد المستند وإنشاء قيده المحاسبي |

صلاحيات إضافية خاصة: `reports.view` / `reports.export` / `reports.custom`، و`settings.view` / `settings.edit` / `settings.users` / `settings.roles` / `settings.audit_log`، و`ai.use` / `ai.settings`، و`core.view` / `core.edit`.

## الأدوار الستة

| الدور | الوصف |
|---|---|
| `super_admin` (مدير النظام الأعلى) | يملك كل الصلاحيات دائماً دون استثناء — تُمنح تلقائياً |
| `admin` (مدير) | كل الصلاحيات **عدا** `core.edit` |
| `manager` (مدير عام) | صلاحيات تشغيلية واسعة بلا حذف |
| `accountant` (محاسب) | محاسبة كاملة + عرض وتحرير مبيعات ومشتريات |
| `sales_rep` (مندوب مبيعات) | مبيعات ونقاط بيع وCRM على مستنداته هو فقط |
| `viewer` (مطالع) | عرض فقط عبر كل الوحدات، بلا أي إضافة أو تعديل أو تصدير |

> الدور يُعرَّف في صفحة الأدوار، ويمكن إنشاء أدوار مخصصة بصلاحيات يدوية. الأدوار النظامية (الجاهزة) محمية من التعديل لكن يمكن **نسخها** لإنشاء دور مخصص انطلاقاً منها. إذا لم تُسنَد صلاحيات صريحة للمستخدم، يطبق النظام الجدول الافتراضي لدوره (الموضح أدناه)، وتُطبق الصلاحيات المسندة يدوياً عند وجودها، والرمز `*` يعني كل الصلاحيات.

## شرح صلاحية «مستنداتي فقط» (own)

- صلاحية `module.own` تعني: هذا المستخدم يرى **مستنداته هو فقط** في الوحدة، لا كل مستندات المنشأة.
- المثال العملي: مندوب مبيعات يملك `sales.own` — يفتح قائمة الفواتير فراه فواتيره هو فقط، والفواتير التي أنشأها زملاؤه لا تظهر له أصلاً.
- الصلاحية تُطبق أيضاً على أدوات الوكيل الذكي: المندوب لا يستطيع عبر «مغزى» قراءة أو تعديل فواتير غيره.
- الهدف: مندوبون وكاشيرون يعملون على بياناتهم دون الاطلاع على أداء الآخرين، بينما يرى `manager` وما فوق كل شيء.
- ملاحظة: مندوب المبيعات يرى أصناف المخزون بـ `inventory.own` للبحث عن الأسعار والكميات، لكنه لا يستطيع التعديل فيها.

## قواعد إضافية مهمة

- **القائمة الجانبية تتكيف تلقائياً**: الوحدات التي لا تملك أي صلاحية عرض أو إنشاء فيها تختفي من القائمة — فالمطالع لا يرى قائمة الإعدادات، والمندوب يرى المبيعات وCRM فقط.
- **الأزرار تختفي مع الصلاحية**: زر «إنشاء فاتورة» مثلاً لا يظهر إطلاقاً لمن لا يملك `sales.create` — لا مجرد تعطيل.
- **الترحيل إجراء منفصل**: ملكية `sales.edit` لا تسمح بالترحيل؛ صلاحية `post` مستقلة لأن ترحيل المستند يُنشئ قيداً محاسبياً مؤثراً.
- **الحذف للمسودات**: حتى أصحاب صلاحية `delete` لا يحذفون مستنداً مُرحّلاً — التصحيح يتم بمرتجع أو قيد عكسي.
- **مفتاح الوكيل الذكي**: تغيير مفتاح المزود أو إيقاف المساعد يتطلب `ai.settings` — غير متاح للمحاسب ولا للمندوب.

## نصائح

- ابدأ بمنح الأدوار الافتراضية ثم خصصها — لا تعطِ `*` لمن لا يحتاجها.
- راجع مصفوفة الصلاحيات ربع سنوياً عند تغير الموظفين.
- استخدم نسخ الدور النظامي لإنشاء دور مخصص (مثلاً «محاسب مشتريات») بدل تعديل الدور الأصلي.
- عند الشك في سبب ظهور/اختفاء عنصر لصالح، تحقق أولاً من صفحة: الإعدادات ← الأدوار ← الصلاحيات.
