# إعدادات POS وتقاريره — دليل الاستخدام

> ضبط سلوك شاشة الكاشير (مفاتيح `pos.*`) وتحليل مبيعات نقاط البيع بفلاتر وتجميع وتصدير.

## نظرة عامة

ملفان في وحدة نقاط البيع:

1. **إعدادات POS** (`/pos/settings`) — إعدادات لكل شركة تُخزَّن في جدول الإعدادات العام تحت مفاتيح تبدأ بـ `pos.`.
2. **تقارير POS** (`/pos/reports`) — تحليل عمليات البيع مع فترات جاهزة وفلاتر وتجميع وتصدير.

---

## إعدادات POS

- **الوصول:** القائمة الجانبية ← نقاط البيع ← الإعدادات.
- **الصلاحية:** إدارة الإعدادات ضمن `settings.*` / `pos.*`.

### الحقول والمفاتيح

| المفتاح | الإعداد | الوصف |
|---|---|---|
| `pos.defaultCashBoxId` | **صندوق النقد الافتراضي** | يُقترح مسبقاً في نافذة «فتح الوردية» — يوفر على الكاشير اختياره كل صباح |
| `pos.defaultWalkInCustomerId` | **العميل النقدي الافتراضي** (Walk-in Customer) | يُستخدم للبيع النقدي الخالص دون اختيار عميل — يظهر اسمه في شريط العميل افتراضياً |
| `pos.receiptFooter` | **نص تذييل الإيصال** | سطر حر يُطبع أسفل كل إيصال 80mm (مثال: «شكراً لزيارتكم — لا استبدال بعد 14 يوماً») |
| `pos.autoPrint` | طباعة تلقائية | طبع الإيصال فور نجاح الدفع دون نقرة إضافية |
| `pos.allowPriceEdit` | السماح بتعديل السعر | تفعيل تعديل سعر الوحدة في السلة — **معطّل افتراضياً** (أمان الصندوق) |
| `pos.allowDiscount` | السماح بالخصم | السماح بإدخال نسبة خصم على سطر السلة — مفعّل افتراضياً |
| `pos.allowNegativeStock` | السماح بالمخزون السالب | السماح ببيع منتج رصيده صفر (المسح يعمل والبلاطة تصبح قابلة لللمس) — **معطّل افتراضياً** |

> **ملاحظة:** القيم تُحفظ نصياً في جدول `settings` (المفاتيح المنطقية `true`/`false`)، وتُطبَّق فور الحفظ على كل شاشات الكاشير الخاصة بالشركة.

### أثر كل مفتاح على سلوك الكاشير

| المفتاح | مفعّل | معطّل |
|---|---|---|
| الطباعة التلقائية | نافذة الطباعة تفتح وحدها بعد كل دفع ناجح | الكاشير يطبع يدوياً من «إعادة طباعة آخر إيصال» |
| تعديل السعر | الكاشير يعدّل سعر الوحدة في سطر السلة | حقل السعر مقفول على سعر البيع من كتالوج المنتج |
| السماح بالخصم | إدخال نسبة خصم لكل سطر | حقل الخصم مخفي ولا يمكن التخفيض عن السعر |
| المخزون السالب | المسح يعمل والبلاطات صفرية الرصيد قابلة لللمس، والبيع يُخصم إلى ما دون الصفر | البلاطة معطلة رمادياً والمسح يرفض المنتج |

### توصيات الضبط

| البيئة | الإعداد المقترح |
|---|---|
| صيدلية/بقالة عالية الدوران | طباعة تلقائية ✓، تعديل سعر ✗، خصم ✗، مخزون سالب ✗ |
| متجر ملابس | طباعة تلقائية ✓، تعديل سعر ✗، خصم ✓ (مدير فقط يعدّل السعر)، مخزون سالب ✗ |
| مطعم/كافتيريا | مخزون سالب ✓ (الجرد لاحقاً)، خصم ✓ |

## تقارير POS

- **الوصول:** القائمة الجانبية ← نقاط البيع ← التقارير.
- **الصلاحية:** `reports.view` للعرض، `reports.export` للتصدير — زر التصدير يظهر فقط لحامل صلاحية التصدير.

### الفترات الجاهزة

اختر من شريط الفترة أعلى التقرير: **اليوم / هذا الأسبوع / هذا الشهر / هذه السنة / الكل** — التقرير يُعاد تحميله عند كل تغيير.

### الفلاتر

| الفلتر | يطابق |
|---|---|
| طريقة الدفع | نقدي / آجل |
| الكاشير | بالاسم (بحث نصي) |
| المنتج | باسم المنتج في بنود الفواتير |
| العميل | باسم العميل (البيع النقدي يظهر باسم العميل النقدي الافتراضي) |

### التجميع حسب

خيار **«تجميع حسب»** يعيد شكل التقرير كلياً:

| التجميع | ماذا يرى المستخدم |
|---|---|
| بدون (تفصيلي) | كل إيصال سطر مستقل برقمه وتاريخه وكاشيره |
| يوم | إجمالي المبيعات لكل يوم |
| ورديـة | كل ورديـة بسطرها (عدد الفواتير، النقد، الآجل) |
| كاشير | أداء كل كاشير في الفترة |
| منتج | المبيعات بالكمية والقيمة لكل منتج (تفصيل بنود) |
| طريقة الدفع | تقسيم نقدي/آجل |

### الفرز والتصدير

- **الفرز:** حسب التاريخ (افتراضي) أو الإجمالي أو الكاشير، تصاعدي/تنازلي.
- **التصدير:** Excel و PDF و HTML — بنفس البيانات المعروضة بعد الفلاتر والتجميع، مع ترويسة هوية الشركة (الشعار واسم الشركة من إعدادات التقارير).

### أعمدة التقرير التفصيلي

| العمود | الوصف |
|---|---|
| رقم الإيصال | `POS-000123` |
| التاريخ/الوقت | لحظة البيع |
| الكاشير | صاحب الوردية |
| العميل | أو «عميل نقدي» |
| المنتجات | أسماء البنود |
| نقدي / آجل | تقسيم الدفع |
| الإجمالي | إجمالي الفاتورة |

## مثال استخدام

تريد معرفة أفضل المنتجات هذا الشهر ومن يبيعها:

1. افتح التقارير ← الفترة: **هذا الشهر**.
2. «تجميع حسب»: **منتج** — فرز تنازلي بالإجمالي.
3. صدّر Excel وأرسله للمشتريات لتخطيط الطلب.

لرصد عجز كاشير: «تجميع حسب»: **كاشير**، وفرز حسب الكاشير، وقارن النقد المحصّل مع شاشة الورديات (فرق كل ورديـة).

## قواعد مهمة

- التقارير تقرأ من **فواتير المبيعات الحقيقية** المعلَّمة POS — أي تقرير مبيعات عام سيتطابق مع تقرير POS لنفس الفترة.
- الفواتير **الملغاة مستبعدة** من كل التجميعات.
- فلترة «المنتج» تُجمع على مستوى **بنود** الفواتير، فيُحتسب الإيصال مرة واحدة عند تجميع الفواتير حتى لا يتضاعف.
- التصدير يخضع لصلاحية `reports.export` — لا زر تصدير لمن لا يملكها.

## أخطاء شائعة وحلولها

| المشكلة | السبب | الحل |
|---|---|---|
| التقرير فارغ | لا مبيعات POS في الفترة المختارة | وسّع الفترة إلى «الكل» للتحقق |
| لا يظهر زر التصدير | صلاحية `reports.export` غير موهوبة | راجع دور المستخدم من إدارة الأدوار |
| أسماء الكاشير «غير معروف» | صفحة فاتورة بلا مستخدم مرتبط (بيانات قديمة) | تجاهل للفترات القديمة — الورديات الجديدة مرتبطة دائماً |
| الإعدادات لا تُطبَّق على جهاز آخر | الإعدادات لكل شركة وليست لكل جهاز — أُخذت من جهاز قبل الحفظ | حدّث شاشة الكاشير (F5) بعد الحفظ |

## نصائح

- راجع تقرير «طريقة الدفع» أسبوعياً وتأكد أن نسبة الآجل تحت السيطرة.
- عند فتح فرع جديد: اضبط صندوق النقد الافتراضي والعميل النقدي الافتراضي وتذييل الإيصال قبل أول وردية.
- صدّر تقرير «الورديـة» نهاية الشهر وأرفقه بمستند إغلاق الشهر لدى المحاسب.
