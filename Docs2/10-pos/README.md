# نقاط البيع (POS) — دليل الاستخدام

> شاشة كاشير هجينة (باركود + لمس) تُنشئ فواتير مبيعات حقيقية مُرحَّلة فوراً مع إيصال حراري وورديات صندوق.

## نظرة عامة

وحدة نقاط البيع هي واجهة بيع سريعة موجهة للكاشير داخل المتجر. بدلاً من فتح شاشة فواتير المبيعات الكاملة، يعمل الكاشير من شاشة واحدة مملوءة للشاشة: يمسح الباركود أو يلمس البلاطات، ثم يستلم النقد ويطبع الإيصال في ثوانٍ.

**متى تستخدم نقاط البيع بدلاً من فاتورة المبيعات العادية؟**

| المعيار | نقاط البيع | فاتورة المبيعات العادية |
|---|---|---|
| طريقة البيع | بيع فوري أمام الزبون | بيع بالطلب/الهاتف/العقود |
| سرعة الإدخال | باركود أو لمسة واحدة | نموذج كامل بحقول متعددة |
| الترحيل | فوري عند الدفع — لا مسودة | مسودة ثم ترحيل يدوي |
| الترقيم | `POS-` (6 خانات محشوّة أصفاراً) | `INV-` |
| الطباعة | إيصال حراري 80mm | مستند A4 |
| الارتباط بالوردية | إلزامي (كل عملية بيع مرتبطة بورديـة) | غير مرتبط |
| الجدول في قاعدة البيانات | نفس جدول `sales_invoices` مع `is_pos = true` + `shift_id` | نفس الجدول |

> **نقطة مهمة:** عملية نقاط البيع ليست «نظاماً موازياً» — كل عملية بيع تُنشئ فاتورة مبيعات حقيقية تظهر في تقارير المبيعات وأعمار الذمم وقائمة الدخل تماماً مثل أي فاتورة أخرى. الفرق في الواجهة وسرعة الدورة فقط.

## الوصول والصلاحيات

- الصلاحية المطلوبة: `pos.view` للعرض، `pos.create` للبيع، `pos.edit` للتعديل، `pos.delete` للحذف، بالإضافة إلى `reports.view` و `reports.export` لتقارير نقاط البيع.
- كل الصفحات محمية بواسطة `PermissionRoute` — المستخدم بلا صلاحية `pos.*` لا يرى الوحدة في القائمة الجانبية إطلاقاً.

| الدور | الوصول |
|---|---|
| `super_admin` | كل شيء |
| `admin` | كل صفحات الوحدة والإعدادات |
| `manager` | الشاشة والورديات والتقارير |
| `accountant` | الورديات والتقارير (لمراجعة فروقات الصندوق) |
| `sales_rep` | شاشة الكاشير (وفق صلاحياته) |
| `viewer` | عرض فقط |

> **ملء الشاشة:** شاشة الكاشير (`/pos`) تُعرض خارج التخطيط العام عمداً — الكاشير لا يحتاج القائمة الجانبية، وأي نقرة خاطئة فيه لا تخرجه من البيع. بقية صفحات الوحدة (`/pos/shifts` وغيرها) تُعرض داخل الهيكل العام كالمعتاد.

## دورة حياة العملية

1. **افتح ورديـة** — اختر صندوق النقد وأدخل مبلغ الافتتاح في الدرج.
2. **بِع** — امسح الباركود أو المس البلاطات، ثم اضغط الدفع (F9).
3. **استلم الدفع** — نقدي، أو آجل، أو مختلط. تُنشأ الفاتورة وتُرحَّل القيد وتُخصم المخازن في عملية واحدة ذرية.
4. **اطبع الإيصال** — طباعة تلقائية بعد الدفع (قابلة للتعطيل) + إعادة طباعة آخر إيصال.
5. **أغلق الوردية** — عدّ نقد الدرج، يُحسب الفرق، ويُطبع تقرير Z.

## نظرة سريعة على الشاشات

### شاشة الكاشير (`/pos`)

- مطالبة فتح ورديـة (صندوق النقد + مبلغ الافتتاح) عند أول دخول باليوم.
- شبكة لمس ببلاطات كبيرة مع شارة مخزون حية، وباركود عتادي عبر حقل بحث موحّد.
- سلة محفوظة محلياً لا تضيع عند التحديث، وسلات معلقة لخدمة عدة زبائن بالتناوب.
- نافذة دفع بثلاثة أوضاع (نقدي / آجل / مختلط) مع حساب الباقي فوراً.

### الورديات (`/pos/shifts`)

- سجل كل الورديات: الافتتاح، الإغلاق، المتوقع، **الفرق** (متوازن/فائض/عجز ملوّن).
- نافذة إغلاق بجرد فعلي للمعدود، وتقرير Z قابل للطباعة 80mm.

### الإعدادات (`/pos/settings`)

- صندوق النقد الافتراضي والعميل النقدي الافتراضي ونص تذييل الإيصال.
- مفاتيح سلوك: طباعة تلقائية، تعديل السعر، الخصم، المخزون السالب.

### التقارير (`/pos/reports`)

- فترات جاهزة (اليوم/أسبوع/شهر/سنة/الكل) وفلاتر (طريقة الدفع، الكاشير، المنتج، العميل).
- تجميع حسب (يوم/ورديـة/كاشير/منتج/طريقة دفع) وتصدير Excel/PDF/HTML.

## نقاط البيع ضمن الصورة الأكبر

توفر الوحدة التكامل التلقائي مع بقية الوحدات — لا إدخال مزدوج إطلاقاً:

| الوحدة المتكاملة | ماذا تتبادل |
|---|---|
| **المبيعات** | كل عملية POS فاتورة مبيعات كاملة (`is_pos = true`) تظهر في قوائم الفواتير وتقارير المبيعات وأعمار الذمم للجزء الآجل |
| **المخازن** | الخصم من المخزون وحركات الخروج تتم في نفس عملية الدفع (من المستودع الأغنى برصيد كل منتج) |
| **المحاسبة** | القيد يُرحَّل لحظياً: صندوق النقد (حساب GL للصندوق) + ذمم مدينة / المبيعات + ضريبة المخرجات |
| **الإعدادات** | العملة، نسبة VAT، الترقيم (`POS-` من التسلسلات)، ومفاتيح `pos.*` |
| **مركز التقارير** | بيانات POS تغذي التقارير المركزية بجانب المبيعات العادية |

## مصطلحات سريعة

| المصطلح | المعنى |
|---|---|
| **الورديـة** (Shift) | فترة عمل الكاشير من فتح الصندوق حتى إغلاقه — كل بيع يرتبط بها |
| **صندوق النقد** (Cash Box) | درج النقد المرتبط بحساب GL في شجرة الحسابات |
| **العميل النقدي الافتراضي** (Walk-in) | عميل افتراضي للبيع النقدي الخالص بلا بطاقة |
| **إيصال نقاط البيع** | الإيصال الحراري 80mm بترقيم `POS-` مستقل عن `INV-` |
| **تقرير Z** | تقرير إغلاق الوردية: المبيعات، النقد، المتوقع، والفرق |

## أسئلة سريعة

| سؤال | جواب مختصر |
|---|---|
| هل تظهر عملية POS في تقارير المبيعات العادية؟ | نعم — إنها فاتورة مبيعات حقيقية معلَّمة `is_pos` |
| هل يمكن بيع آجل للعميل النقدي الافتراضي؟ | لا — الآجل يتطلب عميلاً مسجلاً يضاف رصيده له |
| هل يمكن فتح ورديتين لنفس الكاشير؟ | لا — قاعدة مفروضة على قاعدة البيانات |
| هل يضيع البيع لو انقطع الكهرباء مؤقتاً؟ | السلة محفوظة محلياً — تعود بعد إعادة التشغيل (الدفع غير المنجز يُعاد) |
| من يعدّل سعر البيع في الكاشير؟ | من يحمل صلاحية ذلك فقط بعد تفعيل `pos.allowPriceEdit` (معطّل افتراضياً) |

## قواعد مهمة

- **لا بيع بلا ورديـة مفتوحة** — شاشة الكاشير مقفلة حتى تفتح ورديـة، ووردية واحدة مفتوحة فقط لكل مستخدم (مفروضة على مستوى قاعدة البيانات).
- **الآجل يتطلب عميلاً مسجلاً** — البيع النقدي الخالص يمكن أن يتم للعميل النقدي الافتراضي (Walk-in Customer)، لكن أي جزء آجل يُضاف لرصيد عميل حقيقي.
- **الأرقام تُعاد حسابها على الخادم** — الإجماليات والضريبة تُحسب من بنود الفاتورة داخل العملية نفسها؛ لا يمكن التلاعب بالإجمالي من الواجهة.
- **السلة محفوظة محلياً** — تحديث الصفحة أو انقطاع مؤقت لا يفقد عملية بيع جارية (تُخزَّن في `localStorage`).

## أخطاء شائعة وحلولها

| الرسالة كما تظهر في النظام | السبب | الحل |
|---|---|---|
| «لا توجد ورديـة مفتوحة» | الكاشير لم يفتح ورديـة بعد | اضغط «فتح ورديـة» واختر الصندوق ومبلغ الافتتاح |
| «لديك ورديـة مفتوحة بالفعل» | محاولة فتح ورديـة ثانية لنفس المستخدم | أغلق الوردية الحالية أولاً من شاشة الورديات |
| «يلزم عميل مسجل للبيع الآجل» | دفع مختلط أو آجل بلا عميل | اختر عميلاً من القائمة قبل إتمام الدفع |
| «أُغلقت الوردية أثناء عملية الدفع» | أُغلقت الوردية من جهاز آخر في نفس اللحظة | افتح ورديـة جديدة وأعد عملية الدفع |

## نصائح

- علّق السلة بـ **F10** لخدمة الزبون التالي بسرعة عند ازدحام الطابور.
- اضبط «العميل النقدي الافتراضي» و«صندوق النقد الافتراضي» من الإعدادات مرة واحدة لتسريع فتح الوردية يومياً.
- راجع شاشة الورديات نهاية كل يوم للتأكد من عدم وجود فروق كبيرة في الصناديق.
