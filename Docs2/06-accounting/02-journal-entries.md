# قيود اليومية — دليل الاستخدام

> محرر القيود اليدوية بمحاسبة مزدوجة كاملة: أسطر مدين ودائن متوازنة، فحص توازن حي، وترحيل ذري آمن.

## نظرة عامة

قيود اليومية (Journal Entries) هي سجل الحركات المحاسبية اليدوية — كل ما لا تولّده الفواتير والسندات تلقائياً تسجله هنا: إثبات إهلاك، تسوية بنكية، قيد عكسي، تصحيح خطأ. تصل إليها من: **القائمة الجانبية ← المحاسبة ← قيود اليومية** (`/accounting/journal`).

كل قيد يبدأ **مسودة** ثم **يُرحَّل** (Post) ليعكس أثره في الأرصدة والتقارير. رقم القيد المرجعي يُنشأ تلقائياً من تسلسل المستندات عند الحفظ.

## الوصول والصلاحيات

| الفعل | الصلاحية |
|---|---|
| عرض القائمة والتفاصيل والطباعة | `accounting.view` |
| إنشاء قيد (مسودة) | `accounting.create` |
| تعديل/حذف قيد | `accounting.edit` / `accounting.delete` — **للمسودات فقط** |
| ترحيل قيد | `accounting.post` |

## القائمة

جدول القيود يعرض: التاريخ، المرجع (رقم القيد التلقائي)، البيان، المبلغ، **الحالة** (بشارة: مسودة/مُرحّل)، المستخدم المُنشئ، وأزرار الإجراءات.

- **فلتر الحالة:** اختر «مسودة» أو «مُرحّل» أو الكل، مع بحث بالبيان والمرجع.
- **عرض تفصيل:** يفتح نافذة تُظهر أسطر القيد كاملة (حساب، مدين، دائن، ملاحظة).
- **طباعة:** مستند قيد جاهز بالشعار وبيانات الشركة.

## العرض التفصيلي والطباعة

- **عرض تفصيل:** نافذة تعرض رأس القيد (المرجع، التاريخ، البيان، الحالة، المُنشئ) وجدول الأسطر كاملاً: الحساب، مدين، دائن، ملاحظة — مع الإجماليات أسفلها.
- **الطباعة:** مستند قيد جاهز يتضمن شعار الشركة وبياناتها (الاسم، الرقم الضريبي، العنوان، الهاتف)، ورمز العملة، وأسماء الحسابات مع ملاحظاتها، والمبلغ الإجمالي. لو كانت أسطر القيد غير محمّلة في الذاكرة يجلبها النظام تلقائياً قبل الطباعة.
- **عمود «المُنشئ»** في القائمة يعرض المستخدم الذي أنشأ القيد — مفيد عند المراجعة والفلترة على «مستنداتي فقط» لمن يملك `accounting.own`.

## شاشة القيد الجديد

اضغط **«قيد جديد»**، ستجد:

| الحقل | الوصف |
|---|---|
| التاريخ | يُعبّأ بتاريخ اليوم |
| البيان | وصف عام للقيد |
| **الأسطر** | شبكة متعددة الأسطر: **الحساب، مدين، دائن، ملاحظة** — يبدأ المحرر **بسطرين** فارغين |

**إجماليات حية أسفل الشبكة:** مجموع المدين، مجموع الدائن، وحالة التوازن.

### فحص التوازن — القاعدة الحاكمة

- **الحفظ ك«مُرحّل» محجوب** إلا إذا: **مجموع المدين = مجموع الدائن** **و** المبلغ أكبر من صفر.
- إذا لم يتحقق الشرطان، زر «حفظ ومُرحّلة» معطل ويظهر تنبيه بالفرق: «قيد غير متوازن: الفرق = 5,000 ر.ي».
- القيد غير المتوازن يمكن حفظه **«مسودة»** فقط — أكمل الأسطر ثم رحّله لاحقاً.

## دورة حياة المستند

| الحالة | المعنى | ماذا يمكن فعله فيها |
|---|---|---|
| **مسودة** (Draft) | لم يُرحَّل — لا يؤثر في الأرصدة ولا التقارير | تعديل، حذف، **ترحيل**، طباعة |
| **مُرحّل** (Posted) | مؤثر ماليًا — يدخل في كل التقارير | **قراءة وطباعة فقط** — التعديل والحذف معطلان |

> **القيود المرحّلة غير قابلة للتعديل.** أزرار التعديل والحذف معطلة على أي قيد مُرحّل. التصحيح يتم بـ**قيد جديد أو قيد عكسي** يعكس الأسطر (المدين دائن والعكس)، ثم يُرحَّل.

## حارس التكرار

قبل الحفظ يقارن النظام القيد الجديد بالقيود الموجودة:

| الحالة | السلوك |
|---|---|
| **قيد مطابق تماماً** (نفس التاريخ والبيان ونفس الأسطر بمبالغها) | **حظر تام** — نافذة تُظهر القيد المكرر (مرجعه وتاريخه ومبلغه)، ولا يُحفظ |
| **قيد متقارب** (تشابه عالٍ لكن ليس مطابقة كاملة) | **تحذير** — يعرض القيود المشتبه بها مع نسبة التشابه، ويمكنك التأكيد والمتابعة إذا كان القيد مقصوداً |

فشل فحص التكرار لسبب تقني لا يمنع الحفظ — الحارس وسادة وقاية لا عائق.

## قواعد الترحيل

عند الضغط على «ترحيل» ينفّذ النظام تسلسلاً محكماً:

1. **التحقق من التوازن:** مجموع المدين = مجموع الدائن ضمن سماحية **0.01** (لا تفرّق في التقريب)، وأن المبلغ ليس صفراً.
2. **تنفيذ ذري (Atomic):** تحديث حالة القيد وكتابة أسطره داخل معاملة واحدة — إما أن تنجح كلها أو يتراجع كل شيء.
3. **إعادة المحاولة عند الانسداد:** إذا فشلت المعاملة بسبب تعارض تزامني (deadlock) تُعاد المحاولة تلقائياً.
4. **فحص الاتساق بعد الترحيل:** بعد التنفيذ يتحقق النظام من أن ما حُفظ فعلاً متوازن (مجموع المدين المحفوظ = الدائن المحفوظ)؛ أي انحراف يُرجع خطأ صريحاً.
5. **التسجيل في التدقيق:** كل ترحيل يُسجَّل في سجل التدقيق (حركة «ترحيل») مع المستخدم والوقت.

## سير عمل خطوة بخطوة — مثال رقمي كامل

إثبات مصروف إيجار 150,000 ر.ي نقداً لشهر يونيو:

1. القائمة الجانبية ← المحاسبة ← قيود اليومية ← **«قيد جديد»**.
2. التاريخ: `2026-06-30`. البيان: «إيجار شهر يونيو — صندوق الرئيسي».
3. **السطر الأول:** الحساب = «مصروف الإيجار» (`51101`)، **مدين = 150,000**، دائن فارغ، الملاحظة: «إيجار يونيو».
4. **السطر الثاني:** الحساب = «الصندوق» (`11101`)، مدين فارغ، **دائن = 150,000**.
5. لاحظ الإجماليات الحية: مدين 150,000 = دائن 150,000 — **متوازن** ✓
6. اضغط **«حفظ ومُرحّلة»** (لولا التوازن لكان الزر معطلاً واحفظت مسودة).
7. يُنشأ رقم مرجعي تلقائي (مثل `JV-000123`)، وينعكس أثر القيد فوراً في دفتر الحسابين وميزان المراجعة.

| الحساب | مدين (ر.ي) | دائن (ر.ي) |
|---|---:|---:|
| مصروف الإيجار `51101` | 150,000 | |
| الصندوق `11101` | | 150,000 |
| **الإجمالي** | **150,000** | **150,000** |

### مثال قيد من ثلاثة أسطر (تصفية نقدية عبر بنكين)

استلمت دفعة 200,000: منها 120,000 نقداً للصندوق و80,000 حوّلها العميل إلى حساب البنك مباشرة — قيد واحد بثلاثة أسطر:

| الحساب | مدين (ر.ي) | دائن (ر.ي) |
|---|---:|---:|
| الصندوق `11101` | 120,000 | |
| البنك الأهلي `11102` | 80,000 | |
| العميل — مؤسسة النور `12..` | | 200,000 |
| **الإجمالي** | **200,000** | **200,000** |

الإجماليات الحية ستُظهر التوازن أثناء الكتابة، وزر «حفظ ومُرحّلة» يبقى متاحاً لأن الشرطين متحققان (توازن + مبلغ أكبر من صفر).

### مثال قيد عكسي (تصحيح قيد مرحّل)

اكتشفت أن الإيجار كان 105,000 وليس 150,000. القيد الأصلي مُرحّل وغير قابل للتعديل، فأنشئ قيداً عكسياً بالفرق (أو عكساً كاملاً ثم قيداً صحيحاً):

| الحساب | مدين (ر.ي) | دائن (ر.ي) |
|---|---:|---:|
| الصندوق `11101` | 45,000 | |
| مصروف الإيجار `51101` | | 45,000 |

## قواعد مهمة — ملخص سريع

| القاعدة | التفصيل |
|---|---|
| التوازن شرط الترحيل | مدين = دائن **و** المبلغ > 0، وإلا فمسودة فقط |
| سماحية التقريب | فرق حتى 0.01 مقبول في فحص الترحيل الذري |
| المُرحَّل حريم محمي | لا تعديل ولا حذف ولا حتى تغيير أسطره |
| الرقم المرجعي للنظام | يُولَّد من تسلسل المستندات — لا تكتبه يدوياً |
| كل حركة تُدقَّق | إنشاء وتعديل وحذف وترحيل تظهر كلها في سجل التدقيق |
| الأسطر الفارغة تُتجاهل | لا يُحفظ سطر بلا حساب محدد عند الحفظ |

## أخطاء شائعة وحلولها

| الرسالة | السبب | الحل |
|---|---|---|
| «قيد غير متوازن: الفرق = ...» | المدين ≠ الدائن | عدّل الأسطر حتى يتساوى المجموعان |
| زر «حفظ ومُرحّلة» معطّل | القيد غير متوازن أو المبلغ صفر | صحّح الأسطر، أو احفظ مسودة وأكملها لاحقاً |
| نافذة «قيد مكرر» حظرت الحفظ | قيد مطابق تماماً موجود | راجعه أولاً — إن كان نفس القيد فلا تكرره |
| أزرار التعديل/الحذف معطلة على قيد | القيد مُرحّل | أنشئ قيداً عكسياً لتصحيحه |
| فشل الترحيل برسالة خطأ | تعارض تزامني أو مشكلة اتصال | أعد المحاولة — النظام يعيد تلقائياً عند الانسداد |

## نصائح

- راجع فلتر «مسودة» نهاية كل يوم ورحّل ما اكتمل — المسودات لا تظهر في أي تقرير مالي.
- استخدم خانة «الملاحظة» في كل سطر؛ هي ما يجعل القيد مفهوماً بعد أشهر.
- لا تكرّر ما تولّده الوحدات تلقائياً: فاتورة مبيعات مُرحّلة أنشأت قيدها — لا تدخّله يدوياً.
- اعتمد عادة: أي تصحيح = قيد عكسي جديد + إشارة في بيان القيدين لبعضهما.
- عند القيد متعدد الأسطر، أنجز كل أسطر المدين أولاً ثم الدائن؛ يقلّل أخطاء الاتجاه التي يكشفها فحص التوازن مباشرة.
- انتبه لطبيعة الحساب قبل الاتجاه: حساب أصول/مصروف زيادته **مدين**، والتزامات/حقوق/إيرادات زيادتها **دائن**.
