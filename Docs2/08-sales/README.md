# المبيعات — دليل الاستخدام

> دورة البيع الكاملة: من العميل وعرض السعر حتى الفاتورة المُرحَّلة والمرتجعات — بأثر محاسبي ومخزني ذري.

## نظرة عامة

وحدة المبيعات تدير علاقتك بالعملاء ومستندات البيع كلها: فواتير بضريبة القيمة المضافة وعملات متعددة، عروض أسعار تتحول لفواتير بضغطة، ومرتجعات تُرجع المخزون وتنقص الذمم. كل ترحيل ينفّذ **ذرياً**: قيد يومية + حركة مخزون + رصيد العميل في معاملة واحدة.

تصل إلى الوحدة من: **القائمة الجانبية ← المبيعات** (`/sales`). صفحة المركز تعرض بطاقات التنقل مع عدادات حية.

## الوصول والصلاحيات

| الفعل | الصلاحية |
|---|---|
| عرض العملاء والفواتير والعروض والمرتجعات | `sales.view` |
| إضافة/تعديل مستند | `sales.create` / `sales.edit` |
| حذف مسودة | `sales.delete` |
| ترحيل فاتورة أو مرتجع | `sales.post` |
| رؤية مستنداتك فقط | `sales.own` |

**ملاحظة مهمة عن دور `sales_rep` (مندوب المبيعات):** لا يملك `sales.view` الكامل، بل `sales.own` + `sales.create` — يرى قسم المبيعات في القائمة الجانبية ويستطيع إنشاء مستندات، لكنه **يرى مستنداته فقط** (الفلترة تحدث على مستوى الاستعلام `created_by`). أما `accountant` فيرى كل الفواتير لترحيلها وتحصيلها.

## صفحة مركز المبيعات

عند فتح `/sales` تجد بطاقات تنقل مع عدادات حية:

| البطاقة | المسار | العداد الحي | الوصف |
|---|---|---|---|
| **الفواتير** | `/sales/invoices` | عدد الفواتير | فواتير المبيعات والضريبة والتحصيل |
| **العملاء** | `/sales/customers` | عدد العملاء | بيانات العملاء وكشوف الحسابات والذمم |
| **عروض الأسعار** | `/sales/quotations` | عدد العروض | عروض الأسعار والتحويل إلى فواتير |
| **المرتجعات** | `/sales/returns` | عدد المرتجعات | مردودات العملاء والأثر المخزني والمحاسبي |

## بنية الوحدة

```
المبيعات
├── العملاء           ← بطاقة العميل + كشف الحساب + أعمار الذمم (CUS-)
├── فواتير المبيعات   ← المستند المركزي: مسودة ← ترحيل ← تحصيل (INV-)
├── عروض الأسعار      ← عرض يتحول لفاتورة بضغطة (QOT-)
└── مرتجعات المبيعات  ← مردود مقابل فاتورة أصلية (SR-)
```

## تدفق العمل النموذجي

1. **سجّل العميل** (أو استخدم عميلاً موجوداً) — كود `CUS-` تلقائي.
2. *(اختياري)* **أصدر عرض سعر** `QOT-` وارسله؛ عند القبول اضغط **«تحويل إلى فاتورة»**.
3. **أنشئ الفاتورة** `INV-` كمسودة: بنود بالوحدات المتعددة، خصومات، VAT، عملة.
4. **راجع حارس التكرار** إن ظهر، ثم **رحّل** الفاتورة — يصدر القيد وتُخصم البضاعة ويزيد رصيد العميل.
5. **حصّل** عبر **سند قبض** من وحدة المحاسبة — ينقص رصيد العميل ويقلب حالة الفاتورة (مدفوعة جزئياً/مدفوعة).
6. عند رجوع بضاعة: **مرتجع مبيعات** `SR-` مقابل الفاتورة الأصلية، برحيله يرجع المخزون وينقص الرصيد.

## قواعد مهمة

| القاعدة | التفصيل |
|---|---|
| المسودة لا تؤثر | لا قيد ولا حركة مخزون ولا رصيد قبل **الترحيل** |
| الترحيل ذري | القيد + المخزون + رصيد العميل تنجح معاً أو يتراجع كل شيء |
| الفاتورة النقدية | تُعلَّم **مدفوعة تلقائياً** عند الترحيل ولا تؤثر في رصيد العميل |
| المخزون بالوحدة الأساسية | بند بالكرتونة يخصم كمية أساسية = الكمية × معامل التحويل المثبت |
| المُرحَّل حريم محمي | التعديل والحذف للمسودة فقط؛ المُرحَّلة تصحح بمرتجع |
| الذمم حية | رصيد العميل = الفواتير المُرحَّلة − المدفوعات − المرتجعات المُرحَّلة |

## أخطاء شائعة وحلولها

| الرسالة/الملاحظة | السبب | الحل |
|---|---|---|
| «Cannot delete posted invoice. Cancel it first.» | حاولت حذف فاتورة مُرحّلة | صحّح بمرتجع مبيعات أو ألغِ وفق سياستك |
| «Cannot modify lines of posted invoice…» | تعديل بنود فاتورة مُرحّلة | أنشئ فاتورة جديدة أو مرتجعاً |
| نافذة «مستند مكرر» حظرت الحفظ | حارس التكرار كشف مطابقة تامة | راجع الفواتير المشابهة — لا تحفظ مرتين |
| رصيد العميل لم يتحرك بعد الحفظ | الفاتورة مسودة | رحّل الفاتورة |
| المندوب لا يرى فواتير زملائه | دور `sales_rep` يرى مستنداته فقط | طبيعي — للمراجعة الكاملة استخدم دور محاسب أو مدير |

## نصائح

- اجعل عرض السعر أول خطوة مع العميل الجديد — التحويل للفاتورة يورّث البنود والأسعار بلا إعادة كتابة.
- راجع بطاقة «مسودات» في صفحة الفواتير يومياً — فاتورة منسية لم تُرحَّل = إيراد غير مُثبَت وبضاعة غير مخصومة.
- استخدم تاريخ الاستحقاق بدقة — تقرير **أعمار الذمم** يبني عليه فئات التقادم.
- للبيع النقدي السريع بمتجر صغير فكّر في **نقاط البيع (POS)** بدل فاتورة كاملة.
- علّق على كل فاتورة ملاحظة ذات معنى — تظهر في الطباعة وكشف الحساب.
