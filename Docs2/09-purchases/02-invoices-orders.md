# فواتير الشراء وأوامر الشراء — دليل الاستخدام

> استلام البضاعة من الموردين: فاتورة شراء بنفس قوة فاتورة المبيعات (موحدات، خصومات، VAT، عملات) + أوامر شراء تتحول لفواتير، مع آثار ترحيل ذرية.

## نظرة عامة

فاتورة الشراء (Purchase Invoice) توثّق ما استلمته من مورد وما عليك له. عند الترحيل تنفّذ **ذرياً**: قيد يومية (مدين المخزون + ضريبة مدخلات / دائن ذمم دائنة أو النقد)، **حركات مخزون دخول**، و**زيادة رصيد المورد**. أمر الشراء (Purchase Order) هو الطلب المسبق الذي يتحول لفاتورة عند الاستلام. تصل إليهما من: **القائمة الجانبية ← المشتريات ← الفواتير** أو **← أوامر الشراء**.

## الوصول والصلاحيات

| الفعل | الصلاحية |
|---|---|
| عرض القوائم والتفاصيل | `purchases.view` |
| إنشاء/تعديل مسودة | `purchases.create` / `purchases.edit` |
| حذف مسودة | `purchases.delete` |
| ترحيل فاتورة شراء | `purchases.post` |

## فاتورة الشراء — القائمة

- **بطاقات KPI:** إجمالي عدد الفواتير، القيمة الإجمالية، و**إجمالي المستحق الدائن** (ما عليك للموردين الآن).
- **بحث** برقم الفاتورة والمورد + **فلتر الحالة** + **فلتر المورد** + **ترقيم صفحات** من الخادم + **تصدير Excel/PDF**.

## نموذج فاتورة الشراء الجديدة

بنفس نمط فاتورة المبيعات:

| الجزء | الحقول |
|---|---|
| **الترويسة** | المورد، التاريخ، **تاريخ الاستحقاق**، نوع الدفع (**نقدي** — يظهر اختيار **صندوق النقد** — أو **آجل**)، **العملة + سعر الصرف** مع معاينة المعادل بالعملة الأساسية، ملاحظات |
| **البنود** | المنتج (يظهر المخزون والباركود)، **محدد وحدات متعدد** (تبديل الوحدة يجلب سعر شرائها الخاص)، الكمية، سعر الوحدة، خصم السطر % |
| **الخصم الكلي والضريبة** | خصم مبلغ أو نسبة محدود بالمجموع + **VAT** بسعر الشركة (افتراضي 15%) |

**الحفظ:** يُنشئ الفاتورة **مسودة** برقم ببادئة `PINV-` من تسلسل المستندات.

## دورة حياة فاتورة الشراء

| الحالة | المعنى | ماذا يمكن فعله فيها |
|---|---|---|
| **مسودة** | لم تؤثر في شيء | تعديل، حذف، **ترحيل** |
| **مُرحّلة** | دخل المخزون وزاد رصيد المورد وصدر القيد | سداد عبر سند صرف، قراءة وطباعة |
| **مدفوعة جزئياً** | سُدد جزء بسند صرف | متابعة السداد |
| **مدفوعة** | سُددت كلياً | قراءة وطباعة |
| **ملغاة** | أُلغيت | مستبعدة من كل شيء |

## آثار الترحيل (ذري)

معاملة واحدة تنجح كلها أو يتراجع كل شيء:

1. **قيد اليومية:** مدين **المخزون** بالمجموع (بعد الخصومات) + مدين **ضريبة المدخلات** بالـ VAT / دائن **ذمم دائنة** بالإجمالي — أو دائن **حساب صندوق النقد المختار** إن كانت نقدياً.
2. **حركات مخزون دخول** لكل بند (نوع `in` بمرجع رقم الفاتورة) + **زيادة الكمية** — بالكمية **الأساسية** للوحدات المتعددة.
3. **رصيد المورد يزيد بالمستحق** (الإجمالي − المدفوع) — للفاتورة الآجلة فقط.

**الفاتورة النقدية تُعلَّم مدفوعة تلقائياً** لحظة الترحيل ولا تؤثر في رصيد المورد.

### سداد الموردين

السداد لا يُدار من شاشة الفواتير، بل عبر **سندات الصرف** من وحدة **المحاسبة**: السند المُرحّل يربط بالفواتير المُرحّلة المسددة، ينقص رصيد المورد، ويقلب حالتها **مدفوعة جزئياً** ثم **مدفوعة**.

## أمر الشراء

- **الوصول:** القائمة ← المشتريات ← أوامر الشراء
- **الغرض:** طلب شراء مسبق من مورد قبل الاستلام

| الحقل | الوصف | إلزامي |
|---|---|---|
| **رقم الأمر** | بادئة `PO-` تلقائية | تلقائي |
| **المورد + التاريخ** | أساس الأمر | نعم |
| **التاريخ المتوقع** | متى يُتوقع الاستلام | يُستحسن |
| **نوع الدفع** | نقدي / آجل — يورَّث للفاتورة | اختياري |
| **البنود** | منتجات بكميات وأسعار متوقعة | نعم |

### دورة حياة أمر الشراء

| الحالة | المعنى |
|---|---|
| **مسودة** | تحت الإعداد — قابلة للتعديل والحذف والتحويل |
| **مُرسلة** | وصلت المورد وانتظار التوريد |
| **مستلم جزئياً** | وصل جزء من الكميات |
| **مستلم** | وصل الكل |
| **مُفوتَرة** (Invoiced) | تحولت لفاتورة شراء |
| **ملغاة** | أُلغيت |

### زر «تحويل إلى فاتورة شراء»

يظهر على **المسودة** وينفّذ: ينشئ فاتورة شراء **مسودة** من بنود الأمر مربوطة به (`purchaseOrderId`)، ويعلّم الأمر **مُفوتَراً**. أكمل الفاتورة (VAT، خصومات) ثم رحّلها — عندها يدخل المخزون ويزيد رصيد المورد.

### KPIs أوامر الشراء

المسودات، **المعلق** (المُرسلة + المستلمة جزئياً بانتظار التوريد)، والمُفوتَرة.

## سير عمل خطوة بخطوة — مثال رقمي كامل

شراء 20 كرتونة عصير (معامل 12) من مخازن الخير:

1. القائمة ← المشتريات ← الفواتير ← **«فاتورة جديدة»**.
2. المورد: «مخازن الخير للتوزيع». التاريخ: `2026-09-12`. الاستحقاق: `2026-10-12`. الدفع: **آجل**. العملة: YER.
3. **البند:** «عصير برتقال» — الوحدة: **كرتونة** (يجلب سعر شرائها `6,000`)، الكمية: `20`.
4. المجموع = `120,000`. خصم كلي نسبة `2%` = `2,400` → الصافي `117,600`. VAT 15% = `17,640`. **الإجمالي = `135,240`**.
5. **حفظ** → مسودة `PINV-00030`. راجعها ثم اضغط **«ترحيل»** — الأثر الذري:

| الأثر | التفصيل |
|---|---|
| المخزون | +`20 × 12 = 240` قطعة أساسية، حركة `in` بمرجع `PINV-00030` |
| رصيد المورد | 500,000 + 135,240 = **635,240** ر.ي |

قيد اليومية الناتج:

| الحساب | مدين (ر.ي) | دائن (ر.ي) |
|---|---:|---:|
| المخزون | 117,600 | |
| ضريبة المدخلات (VAT) | 17,640 | |
| ذمم دائنة — مخازن الخير | | 135,240 |
| **الإجمالي** | **135,240** | **135,240** |

*لو كانت نقدياً عبر «الصندوق الرئيسي»: دائن الصندوق 135,240، وتُعلَّم **مدفوعة** تلقائياً دون أثر على رصيد المورد.*

6. لاحقاً صرفت 100,000 بسند صرف مربوط بالفاتورة: الحالة **مدفوعة جزئياً** والرصيد 535,240.
7. *(بالبندية)* لو كان الشراء مسبقاً بأمر `PO-00015`: اضغط «تحويل إلى فاتورة شراء» على المسودة — تُنشأ `PINV-00030` من بنوده ويقلب الأمر **مُفوتَراً**.

## قواعد مهمة

| القاعدة | التفصيل |
|---|---|
| `PINV-` و`PO-` من النظام | ترقيم تلقائي من تسلسل المستندات — لا تكتبه يدوياً |
| المسودة لا تدخل شيئاً | لا مخزون ولا قيد ولا رصيد قبل الترحيل |
| المدخلات مقابل المخرجات | شراء يقيد **ضريبة مدخلات** (أصل يُخصم) بخلاف المبيعات (مخرجات تُدفع) |
| المخزون بالوحدة الأساسية | الكرتونة تدخل 12 قطعة أساسية — المعامل يُثبَّت مع البند |
| الأمر لا يحرّك شيئاً | حتى تحويله لفاتورة وترحيلها — لا أثر مخزني لأمر الشراء |
| السداد من المحاسبة | سندات الصرف هي الطريق الوحيد لسداد الموردين وتقليل الحالات |

## أخطاء شائعة وحلولها

| الرسالة | السبب | الحل |
|---|---|---|
| «Invoice not found or not in draft status» | ترحيل فاتورة مُرحّلة سابقاً | راجع حالتها من القائمة |
| «Cannot delete posted invoice…» | حذف فاتورة غير مسودة | صحّح بمرتجع مشتريات |
| الرصيد لم يزيد بعد الحفظ | الفاتورة مسودة | رحّلها |
| الفاتورة لم تقلب مدفوعة | سند الصرف مسودة أو غير مربوط بالفواتير | رحّل السند واربط الفواتير المسددة |
| المخزون زاد في مستودع غير المتوقع | الترحيل يستخدم أول مستودع منشأ افتراضياً | انقل فوراً بتحويل مخزون إلى المستودع الصحيح |
| أمر الشراء لا يقبل التحويل | حالته ليست مسودة | التحويل من المسودة — أو أنشئ فاتورة يدوياً بالمرجع |

## نصائح

- اعمل بثنائية **أمر ← فاتورة** للطلبات الكبيرة: الأمر يوثّق الاتفاق، والفاتورة توثّق الاستلام الفعلي.
- املأ **تاريخ الاستحقاق** — هو أساس أعمار الذمم الدائنة وترتيب أولويات السداد.
- راجع KPI **إجمالي المستحق الدائن** قبل الالتزام بمشتريات جديدة — يحمي سيولتك.
- اشترِ بالعملة الأصلية للمورد مع سعر صرف صحيح — المعادل بالأساسية يُخزَّن مع الفاتورة للتقارير.
- تطابق ضريبة المدخلات مع الفواتير الضريبية للمورد شهرياً — هي ما ستخصمه من مخرجات VAT.
