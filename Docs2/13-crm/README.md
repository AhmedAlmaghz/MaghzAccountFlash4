# CRM — دليل الاستخدام

> إدارة علاقات العملاء: من عميل محتمل إلى فرصة مكسوبة — قمع بيع صارم المراحل مع مهام وأنشطة وتقارير متابعة.

## نظرة عامة

وحدة CRM تدير دورة البيع قبل الفاتورة: **العملاء المحتملون (Leads)** ← **الفرص (Opportunities)** ← عميل حقيقي بفاتورة. تضم أيضاً **المهام** و**الأنشطة** لمتابعة العمل اليومي، وتقارير قمع وأداء في مركز التقارير.

- **الوصول:** القائمة الجانبية ← CRM.
- **الصلاحيات:** `crm.view` للعرض، `crm.create` للإضافة، `crm.edit` للتعديل، `crm.delete` للحذف.

| الدور | الوصول |
|---|---|
| `super_admin` / `admin` | كل شيء |
| `manager` | كل الشاشات والتقارير |
| `sales_rep` | عملاءه المحتملون وفرصه (وفق صلاحياته) |
| `viewer` | عرض فقط |

## العملاء المحتملون (Leads)

### شاشة العملاء المحتملين

- **الوصول:** CRM ← العملاء المحتملون.

### حقول العميل المحتمل

| الحقل | الوصف | إلزامي |
|---|---|---|
| الاسم | اسم الشخص أو الشركة المحتملة | إلزامي |
| هاتف / بريد / شركة | بيانات التواصل — تُنقل للعميل عند التحويل | اختياري |
| المصدر | من أين جاء (إعلان، توصية، معرض...) | اختياري |
| الحالة | `جديد ← تم التواصل ← مؤهل ← محوَّل/مفقود` | إلزامي |
| التصنيف | **ساخن (Hot) / فاتر (Warm) / بارد (Cold)** | إلزامي |
| القيمة المقدرة | حجم صفقة متوقعة يدعم ترتيب الأولويات | اختياري |
| المسؤول | الموظف المالك للعلاقة | اختياري |
| ملاحظات | وصف حر | اختياري |
| **آخر تواصل** | **يُختم تلقائياً (timestamp)** عند تسجيل أي نشاط مرتبط بالعميل المحتمل — لا يُعدَّل يدوياً | تلقائي |

### دورة حياة العميل المحتمل

| الحالة | المعنى | الانتقالات |
|---|---|---|
| **جديد** | لم يُتواصل معه بعد | ← تم التواصل / مؤهل / مفقود |
| **تم التواصل** | ردّ أو تفاعل أولي | ← مؤهل / مفقود |
| **مؤهل** | جدي بالبيع (احتياج + قدرة) | ← محوَّل / مفقود |
| **محوَّل** | أصبح عميلاً حقيقياً — **الحالة النهائية**؛ العميل المحتمل المحوَّل يخرج من قوائم العمل النشطة | نهائية |
| **مفقود** | خسرت العلاقة | نهائية |

### التحويل لعميل — عملية ذرية

زر **«تحويل لعميل»** ينفّذ في **عملية واحدة (كلها أو لا شيء)**:

1. ينشئ **عميلاً** حقيقياً في مدير العملاء (الجداول نفسها التي تستخدمها المبيعات):
   - **كود تلقائي من التسلسلات** (`CUS-`)
   - بيانات التواصل معبأة من العميل المحتمل (هاتف/بريد/شركة)
   - **رقم ضريبي / حد ائتماني / عنوان** — اختيارية تُدخل في نافذة التحويل
2. يحدّث حالة العميل المحتمل إلى **«محوَّل»**.
3. ينشئ **فرصة أولى اختيارية** باسم «فرصة [اسم العميل المحتمل]» مربوطة بالعميل الجديد — فعّلها إن كانت الصفقة قيد التفاوض فعلاً.

> التحليل الذري يعني: لا يمكن أن يُنشأ عميل بلا تحويل الحالة، أو تتحول الحالة بلا عميل. بعد التحويل يظهر كود العميل (ورابط الفرصة) في رسالة النجاح.

## الفرص (Opportunities)

### شاشة الفرص

- **الوصول:** CRM ← الفرص.

### حقول الفرصة

| الحقل | الوصف | إلزامي |
|---|---|---|
| الاسم | عنوان الصفقة | إلزامي |
| القيمة | القيمة المتوقعة للصفقة | إلزامي |
| المرحلة | آلة المراحل أدناه | إلزامي |
| الاحتمالية (%) | وزن الصفقة — تُضبط تلقائياً 100% عند «مكسبَة» و0% عند «مفقودة» | اختياري |
| تاريخ إغلاق متوقع / عميل / مسؤول / ملاحظات | سياق الصفقة | اختياري |

### آلة المراحل الصارمة

```
جديدة ──▶ مؤهلة ──▶ عرض (Proposal) ──▶ تفاوض ──▶ مكسبَة (won) / مفقودة (lost)
```

| القاعدة | التفصيل |
|---|---|
| **التقدم للأمام فقط** | بين المراحل المفتوحة (جديدة/مؤهلة/عرض/تفاوض) لا يُقبل إلا الانتقال لمرحلة **لاحقة** — لا رجوع للخلف |
| **المكسبَة/المفقودة نهائيتان وتقفلان السجل** | لا تعديل للمرحلة بعدهما إطلاقاً — أي محاولة تُرفض برسالة «لا يمكن تغيير مرحلة فرصة مقفلة» |
| بلوغ **«مكسبَة»** | تُضبط **الاحتمالية 100%** ويُختم **تاريخ الإغلاق** تلقائياً |
| بلوغ **«مفقودة»** | تُضبط الاحتمالية 0% ويُختم تاريخ الإغلاق |
| الانتقال لنفس المرحلة | مقبول (لا تأثير) |

### مؤشرات خط الأنابيب الموزونة

القيمة × الاحتمالية = **القيمة الموزونة** لكل فرصة، ومجموعها عبر الفرق المفتوحة يعطي صورة واقعية لخط الأنابيب (Pipeline): فرصة بـ 1,000,000 YER واحتمالية 40% تزن 400,000 YER — لا 100%.

## المهام

- **الوصول:** CRM ← المهام.

| الحقل | الوصف |
|---|---|
| العنوان / الوصف | ما المطلوب إنجازه |
| تاريخ الاستحقاق | متى يجب إنجازه (المتأخر يظهر بلون تحذيري) |
| الأولوية | منخفضة / متوسطة / عالية |
| الحالة | **معلق ← مكتمل / ملغى** |
| الربط | بعميل محتمل أو فرصة أو عميل |
| المسؤول | من ينفّذها |

## الأنشطة

- **الوصول:** CRM ← الأنشطة — سجل ما حدث فعلاً (عكس المهام = ما يجب أن يحدث).

| الحقل | الوصف |
|---|---|
| النوع | **مكالمة / اجتماع / بريد / زيارة / ملاحظة** |
| الموضوع | عنوان ما حدث |
| التاريخ + المدة | متى وكم استغرق (بالدقائق) |
| الربط | عميل محتمل / فرصة / عميل |
| المسؤول | من نفّذه |

> **الربط مع العملاء المحتملين:** تسجيل نشاط مرتبط بعميل محتمل **يختم تلقائياً** حقل «آخر تواصل» عنده في نفس العملية الذرية — أساس تقرير المتابعات المتأخرة.

## تقارير CRM

من **مركز التقارير** (Reports Hub):

| التقرير | ماذا يجيب |
|---|---|
| **قمع المبيعات (Funnel)** | كم عميلاً محتملاً/فرصة في كل مرحلة — أين تتسرب الصفقات |
| **أداء المندوبين (Rep Performance)** | المبيعات والفرص لكل مسؤول |
| **تحويل العملاء المحتملين (Lead Conversion)** | نسبة المحوَّل من إجمالي العملاء المحتملين ومصادرهم |
| **خط الأنابيب (Opportunity Pipeline)** | القيم والموزون حسب المرحلة |
| **المتابعات المتأخرة (Stale Follow-ups)** | العملاء المحتملون الذين مضى على «آخر تواصل» مدة طويلة — قائمة اتصال فورية |

## سير عمل خطوة بخطوة — مثال كامل

1. **أدخل عميلاً محتملاً:** «مؤسسة النور التجارية»، هاتف، مصدر «معرض صنعاء»، تصنيف **ساخن**، قيمة مقدرة 2,500,000 YER، مسؤول: أحمد.
2. اتصل به وسجّل **نشاط** نوعه «مكالمة» ← الحالة إلى **تم التواصل** و«آخر تواصل» يُختم تلقائياً.
3. بعد اجتماع تأهيلي: الحالة **مؤهل**.
4. اضغط **«تحويل لعميل»**: أدخل الرقم الضريبي وحد ائتماني 500,000 ← يُنشأ عميل `CUS-0042` + فرصة «فرصة مؤسسة النور التجارية» ويتحول المحتمل إلى «محوَّل».
5. تحرك بالفرصة: مؤهلة ← **عرض** (قدّمت عرضاً بـ 2,400,000) ← **تفاوض** ← **مكسبَة** ← الاحتمالية 100% وتاريخ الإغلاق يُختم.
6. أنشئ **مهمة** «متابعة تسليم الدفعة الأولى» بتاريخ استحقاق وأولوية عالية.
7. راجع في مركز التقارير أثر الصفقة في القمع وخط الأنابيب وأداء أحمد.

## قواعد مهمة

- **الفرصة لا ترجع للخلف:** آلة المراحل تجبر على تسجيل قرار حقيقي (مكسوبة/مفقودة) بدل «إعادة فتح» الصفقات الميتة — إحصاءات القمع تبقى صادقة.
- **المحوَّل نهائي:** العميل المحتمل المحوَّل لا يعود قائمة العملاء المحتملين النشطين — استمر بعمله عبر العميل والفرص.
- **آخر تواصل لا يُكتب يدوياً:** تسجيل نشاط هو الطريقة الوحيدة لتحديثه — لا اختصارات.
- **الربط الثلاثي:** المهام والأنشطة ترتبط بعميل محتمل أو فرصة أو عميل — استخدم الربط دائماً ليعمل تقرير المتابعات المتأخرة.

## أخطاء شائعة وحلولها

| الرسالة كما تظهر في النظام | السبب | الحل |
|---|---|---|
| «لا يمكن تغيير مرحلة فرصة مقفلة» | الفرصة مكسبَة أو مفقودة | أنشئ فرصة جديدة للعمل التالي |
| «انتقال غير قانوني من مرحلة … إلى …» | رجوع للخلف أو تخطي غير منطقي | التقدم للأمام فقط بين المراحل المفتوحة |
| العميل المحتمل لا يظهر في القائمة | حالته «محوَّل» أو «مفقود» | راجع فلتر الحالة |
| «آخر تواصل» قديم رغم المكالمات | تُسجَّل الأنشطة بلا ربط بالعميل المحتمل | اربط النشاط عند تسجيله |
| «العميل المحتمل محوَّل بالفعل» | محاولة تحويل مزدوجة (نقر مكرر) | تحقق من كود العميل في رسالة النجاح الأولى |

## نصائح

- صنّف العملاء المحتملين بصدق (ساخن/فاتر/بارد) — تصنيفات واقعية تجعل القمع أداة تنبؤ لا ديكوراً.
- اجعل قاعدة يومية: كل عميل محتمل ساخن لديه نشاط خلال آخر 7 أيام — تقرير «المتابعات المتأخرة» يكشف المخالفين.
- عند خسارة فرصة لا تحذفها — علّمها «مفقودة»؛ بيانات الخسارة تغذي تقرير القمع والتحويل.
- استخدم المهام للوعود (اتصال يوم الخميس) والأنشطة للوقائع (تم الاجتماع ساعة) — الفرق بينهما هو جودة المتابعة.
