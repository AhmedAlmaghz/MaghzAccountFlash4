# المنتجات — دليل الاستخدام

> بطاقة المنتج الكاملة: الباركود وSKU، الوحدات المتعددة بمعاملات التحويل، الأسعار، حدود المخزون، والرصيد الافتتاحي.

## نظرة عامة

المنتج هو العنصر الأساسي الذي تدور حوله كل حركات المخازن والمبيعات والمشتريات. تصل إلى الشاشة من: **القائمة الجانبية ← المخازن ← المنتجات** (`/inventory/products`).

## الوصول والصلاحيات

| الفعل | الصلاحية |
|---|---|
| عرض القائمة وتفاصيل المنتج | `inventory.view` |
| إضافة/تعديل منتج | `inventory.create` / `inventory.edit` |
| حذف منتج | `inventory.delete` — يُحظر إن كان للمنتج حركات |

## قائمة المنتجات

جدول يعرض: الكود، الاسم العربي، الباركود، الوحدة، سعر الكلفة، سعر البيع، التصنيفات، حالة التفعيل، وأزرار الإجراءات.

- **بحث ذكي:** يبحث في الاسم العربي والإنجليزي والكود والباركود وSKU معاً.
- **فلاتر:** التصنيف، نوع المنتج، حالة التفعيل.
- **ترقيم صفحات** من الخادم — القائمة تتحمل آلاف المنتجات.
- **تصدير:** زرّا **Excel** و**PDF** يصدّران القائمة المعروضة (بعد الفلترة).

## شاشة المنتج الجديد

- **الوصول:** القائمة ← المخازن ← المنتجات ← زر **«منتج جديد»**
- **الغرض:** إنشاء بطاقة منتج كاملة

### الحقول

| الحقل | الوصف | إلزامي |
|---|---|---|
| **الكود** | يُولَّد تلقائياً ببادئة `PRD-` من تسلسل المستندات؛ يمكن تعطيل التوليد التلقائي من إعدادات التسلسل وكتابته يدوياً | تلقائي |
| **الاسم العربي / الإنجليزي** | اسم المنتج باللغتين — العربي هو المعروض في الفواتير والتقارير | العربي |
| **الباركود** | المعرّف المسحوب بالقارئ في نقاط البيع؛ اضغط أيقونة الكاميرا **لالتقاط الباركود بالكاميرا** أو أدخله يدوياً | اختياري |
| **SKU** | رمز المخزون الداخلي (Stock Keeping Unit) للفرز والمراجعة | اختياري |
| **الوحدة الأساسية** | وحدة تخزين المخزون (قطعة، كيلو…) — تُخزَّن كل الأرصدة بها | نعم |
| **نوع المنتج** | من أنواع المنتجات المعرفة في الإعدادات | اختياري |
| **التصنيفات** | **متعددة** — اختر تصنيفاً أو أكثر من تصنيفات المنتجات | اختياري |
| **سعر الكلفة** | تكلفة الشراء المبدئية — تستخدمها القيود وتقييم المخزون | نعم |
| **سعر البيع** | سعر البيع الافتراضي للوحدة الأساسية | نعم |
| **الصورة** | **رفع ملف صورة أو التقاط بالكاميرا** — تظهر في البطاقة ونقاط البيع | اختياري |
| **الحد الأدنى للمخزون** | عند النزول تحته يظهر الصنف في تنبيه النقص | اختياري |
| **الحد الأقصى للمخزون** | سقف التخزين المرغوب | اختياري |
| **نقطة إعادة الطلب** | الكمية التي يستحسن عندها إصدار أمر شراء | اختياري |
| **مفعّل** | المنتج غير المفعّل لا يظهر في الفواتير الجديدة | نعم |

### الرصيد الافتتاحي

قسم خاص يظهر عند **إنشاء** المنتج فقط:

| الحقل | الوصف |
|---|---|
| **الرصيد الافتتاحي (الكمية)** | الكمية المتاحة قبل بدء استخدام النظام |
| **المستودع الافتتاحي** | المستودع الذي توضع فيه الكمية |

**كيف يُرحَّل:** عند الحفظ تُنشأ **حركة مخزون** واحدة بالكمية في المستودع المختار + **قيد اليومية**: مدين «المخزون» × الكمية × سعر الكلفة / دائن «حساب حقوق الملكية الافتتاحية». ثم **يُقفل** الحقل — لا يمكن إدخال رصيد افتتاحي ثانٍ من نفس النافذة (تصحيح ما بعد ذلك يكون بتسوية جرد).

### الوحدات المتعددة لكل منتج (قسم مهم)

لكل منتج جدول وحدات خاص به؛ كل وحدة صف مستقل فيه:

| الحقل | الوصف |
|---|---|
| **الوحدة** | من وحدات القياس المعرفة في الإعدادات (كرتونة، دزينة…) |
| **معامل التحويل** | كم وحدة أساسية تعادلها — مثال: كرتونة = 12 |
| **سعر البيع الخاص** | سعر بيع هذه الوحدة؛ يُقترح تلقائياً = سعر البيع الأساسي × المعامل ويمكن تعديله |
| **سعر الشراء الخاص** | نفس المنطق بسعر الكلفة |
| **باركود خاص** | اختياري — بعض الشركات تضع باركوداً مختلفاً للكرتونة |
| **الوحدة الأساسية** | علم `is_base` — معاملها 1 دائماً وترتبط بأسعار البطاقة |
| **وحدة البيع الافتراضية** | تُختار تلقائياً عند بيع المنتج |
| **وحدة الشراء الافتراضية** | تُختار تلقائياً عند الشراء |

**قواعد حاكمة:**

- **المخزون يُخزَّن دائماً بالوحدة الأساسية** — بيع كرتونة (معامل 12) يخصم 12 وحدة أساسية.
- **المستندات تثبّت المعامل لحظة الإنشاء:** عند حفظ بند فاتورة يُخزَّن `unit_factor` و`base_quantity` مع البند؛ تعديل المعامل لاحقاً لا يغيّر المستندات القديمة.
- كل منتج يحتفظ دائماً بوحدة أساسية واحدة على الأقل — لا يمكن حذف الوحدة الوحيدة.
- وحدة أساسية واحدة، ووحدة بيع افتراضية واحدة، ووحدة شراء افتراضية واحدة لكل منتج (اختيار واحدة تُلغي العلم من البقية تلقائياً).
- تعديل سعر الكلفة أو البيع في البطاقة **يزامِن** الوحدة الأساسية تلقائياً.

## نافذة تفاصيل المنتج

اضغط على أي منتج لتفتح نافذة بتبويبات:

| التبويب | المحتوى |
|---|---|
| **البيانات** | كل حقول البطاقة + التصنيفات + الصورة |
| **الوحدات** | جدول الوحدات المتعددة مع المعاملات والأسعار والأعلام |
| **المخزون حسب المستودع** | الرصيد لكل مستودع، مع تلوين الحالة: **حرج** (تحت الحد الأدنى) / **تحذير** (وصل نقطة إعادة الطلب) / طبيعي |

## دورة حياة المنتج

| الحالة | المعنى | ماذا يمكن فعله |
|---|---|---|
| **مفعّل** | يظهر في كل المستندات والتقارير | بيعه وشراؤه وتحويله |
| **غير مفعّل** | مخفي عن المستندات الجديدة، ويبقى في التقارير التاريخية | تعديل بياناته، إعادة التفعيل |
| **محذوف** | محذوف نهائياً — لا يُحذف إلا إن لم توجد له حركات | — |

## سير عمل خطوة بخطوة — مثال رقمي

إضافة منتج «عصير برتقال» مع وحدات متعددة:

1. القائمة الجانبية ← المخازن ← المنتجات ← **«منتج جديد»**.
2. الكود: تولّد تلقائياً `PRD-00012`. الاسم العربي: «عصير برتقال». الاسم الإنجليزي: `Orange Juice`.
3. الوحدة الأساسية: «قطعة». النوع: «مشروبات». التصنيفات: «مشروبات» + «مواد غذائية».
4. سعر الكلفة: `500` ر.ي، سعر البيع: `750` ر.ي.
5. الباركود: التقطه بالكاميرا أو أدخل `6201120001234`. SKU: `OJ-1L`.
6. الحد الأدنى: `24`، نقطة إعادة الطلب: `48`، الحد الأقصى: `500`.
7. الرصيد الافتتاحي: `240` قطعة في «المستودع الرئيسي».
8. في قسم **الوحدات** أضف صف «كرتونة»: المعامل `12`، سعر البيع المقترح `750 × 12 = 9,000` ر.ي، سعر الشراء المقترح `500 × 12 = 6,000` ر.ي. علّمها **وحدة بيع افتراضية**.
9. اضغط **حفظ** — تُنشأ حركة افتتاحية: 240 قطعة في المستودع الرئيسي، وقيد بمبلغ `240 × 500 = 120,000` ر.ي:

| الحساب | مدين (ر.ي) | دائن (ر.ي) |
|---|---:|---:|
| المخزون | 120,000 | |
| حقوق الملكية الافتتاحية | | 120,000 |

10. عند بيع «كرتونة» واحدة لاحقاً، يخصم المخزون `12` قطعة أساسية بالضبط.

## قواعد مهمة

| القاعدة | التفصيل |
|---|---|
| كود فريد | كود المنتج لا يتكرر داخل نفس الشركة |
| الافتتاحي مرة واحدة | يُرحَّل مرة واحدة فقط ثم يُقفل — ما بعده تسويات جرد |
| الوحدة الأساسية مرجع كل شيء | المعاملات والأسعار الخاصة تُقاس دائماً نسبة إليها |
| تثبيت المعامل في المستندات | `unit_factor` و`base_quantity` يُخزَّنان مع كل بند لحظة الحفظ |
| الحذف محمي | منتج له حركات لا يُحذف — عطّله بدلاً من حذفه |

## أخطاء شائعة وحلولها

| الرسالة | السبب | الحل |
|---|---|---|
| «Cannot delete the only unit of a product» | حاولت حذف وحدة المنتج الوحيدة | أضف وحدة أخرى أولاً، ووحدة أساسية تبقى دائماً |
| «Cannot delete customer/product with existing…» | المنتج له فواتير أو حركات | عطّل المنتج بدل الحذف |
| الرصيد الافتتاحي لا يُقبل بعد الإنشاء | الحقل مقفل بعد أول حفظ | استخدم تسوية مخزون أو حركة يدوية |
| الباركود لا يعمل في نقاط البيع | باركود غير مطابق أو منتج غير مفعّل | تأكد من صيغة الباركود وتفعيل المنتج |
| سعر الكرتونة لم يتغير مع تعديل سعر القطعة | الأسعار الخاصة مستقلة عمداً | عدّل سعر الوحدة يدوياً من تبويب الوحدات |

## نصائح

- استخدم SKU متسقاً (`فئة-حجم` مثل `OJ-1L`) — يسهّل الفرز والتصدير.
- املأ الحد الأدنى ونقطة إعادة الطلب من أول يوم — تقرير تنبيه النقص يعتمد عليهما.
- اجعل وحدة البيع الافتراضية هي الأكثر تداولاً (غالباً الكرتونة للجملة) لتقليل نقرات الكاشير.
- راجع تبويب «المخزون حسب المستودع» قبل إنشاء أي تحويل بين مستودعات.
- لا تُكرّر الاسم بين عربي وإنجليزي بحروف لاتينية — الاكتمال باللغتين يحسّن البحث.
