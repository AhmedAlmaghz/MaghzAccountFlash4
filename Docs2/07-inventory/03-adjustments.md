# تسويات المخزون (الجرد) — دليل الاستخدام

> توثيق فروقات الجرد الفعلي بين الكمية الدفترية والفعلية، بدورة اعتماد وترحيل يولّد القيد ويصحح الرصيد.

## نظرة عامة

التسوية هي المستند الرسمي لفروقات الجرد: عطل، تلف، ضياع، أو خطأ عدّ. تصل إليها من: **القائمة الجانبية ← المخازن ← التسويات** (`/inventory/adjustments`).

## الوصول والصلاحيات

| الفعل | الصلاحية |
|---|---|
| عرض القائمة | `inventory.view` |
| إنشاء/تعديل تسوية | `inventory.create` / `inventory.edit` |
| اعتماد تسوية | `inventory.edit` |
| ترحيل تسوية | `inventory.edit` (بعد الاعتماد) |
| حذف | `inventory.delete` — **للمسودات فقط** |

## شاشة التسويات

- **الوصول:** القائمة ← المخازن ← التسويات
- **الغرض:** إدارة دورة الجرد كاملة من الإدخال حتى الترحيل

### KPIs أعلى الشاشة

| المؤشر | الوصف |
|---|---|
| **مسودات** | تسويات لم تُعتمد بعد |
| **معتمدة** | بانتظار الترحيل |
| **مُرحّلة** | نفّذ أثرها المخزني والمحاسبي |
| **الفروقات الموجبة** | مجموع الزيادات (واقع أكثر من الدفتري) |
| **الفروقات السالبة** | مجموع النواقص المطلقة |
| **صافي الفرق** | الموجب ناقص السالب |

### حقول التسوية

| الحقل | الوصف | إلزامي |
|---|---|---|
| **رقم التسوية** | بادئة `ADJ-` من تسلسل المستندات | تلقائي |
| **التاريخ** | تاريخ الجرد | نعم |
| **المنتج** | الصنف المجرود | نعم |
| **المستودع** | موقع الجرد | نعم |
| **كمية النظام** | الرصيد الدفتري الحالي — يظهر تلقائياً للمراجعة | نعم |
| **الكمية الفعلية** | ما عُدّ على الرفوف فعلاً | نعم |
| **الفرق** | **يُحسب تلقائياً** = الفعلي − النظامي (يظهر ملوناً: أخضر للموجب، أحمر للسالب) | تلقائي |
| **السبب** | تلف، عطل، خطأ قياس… يظهر في القيد وسجل الحركات | اختياري |
| **كلفة الوحدة** | الكلفة المستخدمة لتقييم الفرق في القيد | اختياري |

## دورة حياة المستند

| الحالة | المعنى | ماذا يمكن فعله فيها |
|---|---|---|
| **مسودة** | أدخلت النتيجة ولم يراجعها أحد | تعديل، حذف، **اعتماد** |
| **معتمد** | راجعها صاحب الصلاحية ووافق عليها | **ترحيل** — التعديل مغلق |
| **مُرحّل** | نُفِّذ أثرها: تصحيح رصيد + قيد يومية | قراءة فقط |
| **مرفوض** | استُبعدت دون تنفيذ | قراءة فقط |

## سير العمل — إضافة ← اعتماد ← ترحيل

1. **إضافة:** أدخل الجرد الفعلي؛ النظام يحسب الفرق تلقائياً ويحفظ **مسودة**.
2. **اعتماد:** زر «اعتماد» يسجل المعتمِد ووقته وتقلب الحالة إلى **معتمد**.
3. **ترحيل:** زر «ترحيل» (يظهر على المعتمدة فقط) ينفّذ **معاملة ذرية** واحدة:

| خطوة الترحيل | الأثر |
|---|---|
| حركة مخزون | سجل بنوع `adjustment` بمرجع `ADJ-…` والسبب |
| تصحيح الرصيد | **يُضبط رصيد الصنف على الكمية الفعلية** في المستودع المعني |
| قيد اليومية | **يُولَّد فقط إذا كان الفرق غير صفري**: قيمة الفرق = الفرق × كلفة الوحدة |

**القاعدة الحاكمة: الفرق الصفري لا يمكن ترحيله** — النظام يمنعه برسالة صريحة؛ التسوية ذات الفرق صفر لا قيد ولا تصحيح تحتاجها أصلاً.

### أثر القيد المحاسبي

| الفرق | الحساب المدين | الحساب الدائن |
|---|---|---|
| **سالب** (نقص — عجز جرد) | مصروف عجز/عطل المخزون | المخزون |
| **موجب** (زيادة — فضل جرد) | المخزون | إيراد فضل المخزون |

قيمة القيد = `الفرق × كلفة الوحدة` — لذلك املأ كلفة الوحدة بدقة.

## سير عمل خطوة بخطوة — مثال رقمي

جرد «عصير برتقال» في المستودع الرئيسي: الدفتر 180 قطعة، الفعلي 176:

1. القائمة ← المخازن ← التسويات ← **«تسوية جديدة»**.
2. المنتج: «عصير برتقال». المستودع: المستودع الرئيسي. التاريخ: `2026-09-12`.
3. كمية النظام تظهر: `180`. أدخل الفعلية: `176` → **الفرق يُحسب تلقائياً: −4**.
4. السبب: «تلف تغليف». كلفة الوحدة: `500` ر.ي.
5. **حفظ** → تسوية `ADJ-00003` **مسودة** (الرصيد لم يتغير بعد).
6. راجع النتيجة مع أمين المخزن ثم اضغط **«اعتماد»**.
7. اضغط **«ترحيل»** — أثر واحد ذري:

| الأثر | التفصيل |
|---|---|
| حركة مخزون | `adjustment` بكمية 4، مرجع `ADJ-00003`، السبب «تلف تغليف» |
| الرصيد الجديد | 176 قطعة في المستودع الرئيسي |
| قيمة الفرق | 4 × 500 = **2,000 ر.ي** |

قيد اليومية الناتج:

| الحساب | مدين (ر.ي) | دائن (ر.ي) |
|---|---:|---:|
| مصروف عجز المخزون | 2,000 | |
| المخزون | | 2,000 |

لو كان الجرد 183 بدل 180 (فضل +3) لانعكس القيد: مدين المخزون 1,500 / دائن إيراد فضل المخزون 1,500.

## قواعد مهمة

| القاعدة | التفصيل |
|---|---|
| الفرق تلقائي | لا تكتب الفرق يدوياً — يُحسب من (الفعلي − النظامي) |
| الاعتماد قبل الترحيل | لا ترحيل من مسودة مباشرة |
| الفرق الصفري يُرفض ترحيله | لا قيمة محاسبية ولا تصحيح رصيد يبرره |
| الترحيل يضبط الرصيد على الفعلي | لا يجمع ولا يطرح — الرصيد النهائي = الكمية الفعلية |
| المُرحَّلة ثابتة | لا تعديل ولا حذف — التصحيح بتسوية جديدة معكوسة |
| الكلفة تُقيّم الفرق | قيمة القيد = الفرق × كلفة الوحدة المدخلة |

## أخطاء شائعة وحلولها

| الرسالة | السبب | الحل |
|---|---|---|
| «لا يمكن ترحيل تسوية بفرق صفر» | الفعلي = النظامي | لا حاجة للترحيل — أبقها كسجل جرد أو احذفها |
| زر «ترحيل» لا يظهر | التسوية مسودة (لم تُعتمد) | اعتمدها أولاً |
| زر التعديل معطل | التسوية معتمدة أو مُرحّلة | التعديل للمسودات فقط؛ صحّح بتسوية جديدة |
| القيد خرج بقيمة غير متوقعة | كلفة الوحدة فارغة أو خاطئة | راجع كلفة الوحدة قبل الترحيل — لا تعديل بعده |
| الرصيد تغير في مستودع مختلف عن المتوقع | اختير مستودع خاطئ عند الإدخال | التسوية مُرحّلة ثابتة — أنشئ تسوية تصحيحية بالمستودع الصحيح |

## نصائح

- اجعل من يعتمد شخصاً غير من أدخل الجرد — فصل بسيط يكشف أخطاء الإدخال.
- املأ **السبب** دائماً: هو ما يظهر في قيد اليومية وسجل الحركات ويجعل المراجعة لاحقاً ممكنة.
- راجع بطاقتي «الفروقات الموجبة» و«الفروقات السالبة» شهرياً — نمط نواقص متكرر يعني مشكلة أمنية أو إجرائية.
- قبل الترحيل تأكد أن كلفة الوحدة تعكس كلفة المنتج الحالية، لأن قيمة القيد تُبنى عليها.
- أجرِ الجرد على أصناف محدودة دورياً (جرد دائري) بدل إغلاق المخزن كاملاً.
