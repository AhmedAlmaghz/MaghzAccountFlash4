# المستخدمون والأدوار والصلاحيات — دليل الاستخدام

> من هنا تتحكم بمن يدخل النظام، وماذا يرى، وماذا يفعل — مع سجل تدقيق كامل لكل حركة حساسة.

## نظرة عامة

تدير هذه المنطقة ثلاث صفحات مترابطة:

| الصفحة | المسار | الغرض |
|---|---|---|
| **المستخدمون** | القائمة الجانبية ← الإعدادات ← المستخدمون (`/users`) | إنشاء الحسابات وتعيين الأدوار والفروع |
| **الأدوار** | القائمة الجانبية ← الإعدادات ← الأدوار (`/roles`) | تعريف مجموعات الصلاحيات (الأدوار المدمجة والأدوار المخصصة) |
| **سجل التدقيق** | القائمة الجانبية ← الإعدادات ← سجل العمليات (`/audit-logs`) | مراجعة كل حركة حساسة بعد وقوعها |

الفكرة المحورية: **لا تعطي صلاحية للمستخدم مباشرة — أنشئ دوراً واجعل الدور يحمل الصلاحيات، ثم أضف المستخدم إلى الدور.**

## الوصول والصلاحيات

| الصفحة | الصلاحية المطلوبة | ملاحظات |
|---|---|---|
| المستخدمون | `settings.users` | من دونها يُعاد التوجيه تلقائياً للوحة التحكم |
| الأدوار | `settings.roles` | أزرار الإنشاء والتعديل تظهر فقط لمن يملك `settings.edit` |
| سجل التدقيق | `settings.audit_log` | من دونها تظهر شاشة رفض واضحة مع شرح الصلاحية الناقصة |

**الأدوار المدمجة ووصولها المختصر:**

| الدور | المدى |
|---|---|
| `super_admin` (مدير النظام الأعلى) | كل شيء دون استثناء |
| `admin` (مدير) | كل شيء **عدا** `core.edit` |
| `manager` (مدير عام) | عرض وإنشاء وتعديل وترحيل في أغلب الوحدات، عرض الإعدادات، تصدير التقارير |
| `accountant` (محاسب) | المحاسبة كاملة (عرض/إنشاء/تعديل/ترحيل)، المبيعات والمشتريات بلا حذف، التقارير مع التصدير |
| `sales_rep` (مندوب مبيعات) | `sales.own` + `sales.create` + `sales.edit` **بدون** `sales.view` — يرى وحدة المبيعات لكن مستنداته فقط، وكذلك `pos.own` و `crm.own` |
| `viewer` (مطالع) | عرض فقط في كل الوحدات التشغيلية، بلا إنشاء ولا تعديل ولا تصدير |

## نموذج الصلاحيات

كل صلاحية تُكتب بصيغة `الوحدة.الفعل`، وتُعرض في شبكة مجمعة حسب الوحدة:

### صلاحيات الوحدات التشغيلية

| الصلاحية | المعنى |
|---|---|
| `module.view` | **عرض كامل** — يرى كل مستندات الشركة في الوحدة |
| `module.own` | **«مستنداتي فقط»** — تُفلتر القوائم تلقائياً لتُظهر مستندات المستخدم نفسه فقط |
| `module.create` | إنشاء مستندات جديدة |
| `module.edit` | تعديل المستندات |
| `module.delete` | حذف المستندات |
| `module.post` | **الترحيل** — متاح في المحاسبة (`accounting.post`) والمبيعات (`sales.post`) ونقاط البيع (`pos.post`) والتصنيع (`manufacturing.post`)؛ الترحيل يُنشئ القيد المحاسبي ويقيّد التعديل |

> **ملاحظة مهمة عن `own`:** المستخدم الذي يملك `sales.own` بدون `sales.view` لا يُحجب من القائمة — يرى الوحدة كاملة لكن القوائم تعرض مستنداته هو فقط. هكذا يعمل المندوب: يسجل فواتيره ويرى فواتيره، ولا يطّلع على فواتير زملائه.

### صلاحيات خاصة

| المجموعة | الصلاحيات |
|---|---|
| **التقارير** | `reports.view` (عرض) / `reports.export` (تصدير Excel وPDF) / `reports.custom` (منشئ التقارير المخصص) |
| **الإعدادات** | `settings.view` (عرض) / `settings.edit` (تعديل الإعدادات) / `settings.users` / `settings.roles` / `settings.audit_log` |
| **الذكاء الاصطناعي** | `ai.use` (استخدام الوكيل الذكي «مغزى») / `ai.settings` (إعدادات الوكيل) |
| **النظام** | `core.view` / `core.edit` |
| **الدور الشامل** | `*` — يعطي كل الصلاحيات دون استثناء (استخدمه بحذر شديد) |

## شاشة المستخدمون (`/users`)

- **الوصول:** القائمة الجانبية ← الإعدادات ← المستخدمون
- **الغرض:** إدارة حسابات الدخول وربطها بالأدوار والفروع.
- **الفلاتر:** مربع بحث (اسم المستخدم)، وقائمة منسدلة **للتصفية حسب الدور** (أدمن / مدير / محاسب / مندوب مبيعات / مشاهد فقط / كل الأدوار).
- **الجدول:** يعرض اسم المستخدم (مع صورة رمزية من الحرف الأول)، البريد، الدور (بشارة)، الفرع، الحالة (نشط/غير نشط).

### إضافة / تعديل مستخدم

اضغط **«مستخدم جديد»** أو أيقونة التعديل بجانب الصف:

| الحقل | الوصف | إلزامي |
|---|---|---|
| اسم المستخدم | معرّف الدخول، يظهر في سجل التدقيق | نعم |
| البريد الإلكتروني | للتواصل والاسترجاع | اختياري |
| الاسم الكامل | الاسم المعروض | اختياري |
| رقم الهاتف | للتواصل | اختياري |
| الدور | يحدد الصلاحيات (انظر نموذج الصلاحيات أعلاه) | نعم (الافتراضي: محاسب) |
| الفرع | ربط المستخدم بفرع معين، أو «كل الفروع» | اختياري |
| حساب نشط | إلغاء التحديد يمنع الدخول مع الاحتفاظ بالحساب | افتراضياً مفعّل |

### الإجراءات على المستخدم

| الإجراء | كيف يعمل |
|---|---|
| **عرض التفاصيل** | نافذة تعرض البريد والهاتف والفرع والاسم الكامل وتاريخ الإنشاء وآخر دخول |
| **إعادة تعيين كلمة المرور** | أيقونة المفتاح ← أدخل كلمة المرور الجديدة ← تأكيد |
| **تعطيل / تفعيل** | أيقونة التبديل مع نافذة تأكيد؛ التعطيل يمنع الدخول دون حذف تاريخ المستخدم |
| **حذف** | أيقونة الحذف مع نافذة تأكيد حمراء |

> **القاعدة الذهبية: لا يمكنك حذف نفسك ولا تعطيل نفسك ولا إعادة تعيين كلمتك من هنا.** أزرار الحذف والتعطيل وإعادة كلمة المرور **معطّلة** تماماً على صف حسابك الحالي. هذا يمنع قفل النظام بالخطأ.

## شاشة الأدوار (`/roles`)

- **الوصول:** القائمة الجانبية ← الإعدادات ← الأدوار
- **الغرض:** تعريف من يفعل ماذا، بمجموعات صلاحيات قابلة لإعادة الاستخدام.
- **العرض:** بطاقات أدوار في شبكة؛ كل بطاقة تعرض الاسم والوصف وشارات الصلاحيات (أول 6 شارات ثم `+N` للبقية)، وبشارة **قفل «نظامي»** للأدوار المدمجة.
- **البحث:** مربع بحث بالاسم.

### إنشاء / تعديل / نسخ / حذف دور

| الإجراء | التفاصيل |
|---|---|
| **دور جديد / تعديل** | نافذة كبيرة فيها الاسم (إلزامي) والوصف + **شبكة الصلاحيات** |
| **نسخ (Clone)** | ينشئ دوراً جديداً باسم «[اسم الدور] - نسخة» بنفس الصلاحيات — أسرع طريق لبناء دور مخصص من دور قريب |
| **حذف** | بنافذة تأكيد — **غير متاح للأدوار النظامية** |

### شبكة الصلاحيات

تُعرض مجمعة حسب الوحدة (النظام، الحسابات، المخازن، المبيعات، نقاط البيع، المشتريات، التصنيع، الموارد البشرية، علاقات العملاء، التقارير، الإعدادات، المساعد الذكي):

- اضغط **اسم الوحدة** في العمود الأيمن = **«تحديد الكل»** لصلاحيات تلك الوحدة (واضغط مجدداً لإلغائها).
- أو فعّل/أطفئ كل صلاحية بمفردها كزر منفصل.
- مربع الوحدة يظهر: علامة صح (كلها محددة)، مربع ممتلئ جزئياً (تحديد جزئي)، أو فارغ (لا شيء).
- عدّاد أعلى الشبكة يعرض عدد الصلاحيات المحددة.

## الأدوار النظامية (isSystem) — مقفلة

الأدوار المدمجة (مثل مدير النظام الأعلى والمحاسب والمطالع) تحمل علامة **«نظامي»** مع أيقونة قفل، وعندها:

1. **لا تعديل ولا حذف** — حقل الاسم والوصف معطّلان، شبكة الصلاحيات باهتة وغير قابلة للنقر، وزر الحذف غير موجود.
2. زر الحفظ يظهر بعنوان **«للقراءة فقط»** ومعطّل.
3. يظهر **تحذير أصفر** أعلى النافذة: «دور نظامي — للقراءة فقط».

**الحل العملي:** اضغط **«نسخ»** على الدور النظامي، عدّل النسخة كما تشاء، واحفظها كـ**دور مخصص**، ثم عيّن المستخدمين إليه. هكذا توسّع النظام دون المساس بالأدوار الأساسية.

## حماية المسارات — إخفاء القائمة ليس حماية

إخفاء عنصر من القائمة الجانبية مجرد تسهيل بصري. الحماية الحقيقية على مستويين:

1. **القائمة الجانبية** تُخفي الوحدات التي لا يستطيع المستخدم الوصول إليها (`module.view` أو `module.own` أو `module.create`).
2. **كل مسار محمي على مستوى الرابط:** كتابة `/accounting` مباشرة في شريط العنوان من دون `accounting.view` **لا تفتح الصفحة** — يُعاد التوجيه تلقائياً إلى لوحة التحكم. وينطبق نفس الأمر على `/users` و `/roles` و `/audit-logs`.

كذلك تنتهي الجلسة تلقائياً بعد **30 دقيقة** من عدم النشاط (تُحدَّث مع كل نقرة أو ضغطة مفاتيح أو تمرير).

## شاشة سجل التدقيق (`/audit-logs`)

- **الوصول:** القائمة الجانبية ← الإعدادات ← سجل العمليات
- **الغرض:** سجل **قراءة فقط** لكل الحركات الحساسة — لا يُعدَّل ولا يُحذف منه شيء.
- **ماذا يسجل:** إنشاء، تعديل، حذف، ترحيل، إلغاء، دخول، خروج، إعادة كلمة مرور، تفعيل/تعطيل مستخدم.
- **الفلاتر (5):** المستخدم، الجدول (مستخدمون، أدوار، حسابات، قيود، منتجات، عملاء، فواتير مبيعات، فواتير مشتريات، موظفون، مستودعات)، الحركة، من تاريخ، إلى تاريخ — مع زر «إعادة تعيين الفلاتر».
- **التفاصيل لكل سجل:** المستخدم (بصورة رمزية)، الحركة بشارة ملوّنة، الجدول، معرّف السجل، والوقت والتاريخ. السجلات الخاصة بالتعديل تحفظ **القيم القديمة/الجديدة**، وتُسجَّل **عنوان IP** للعملية.
- **التصدير:** زر Excel وزر PDF — يصدّران القائمة الحالية (بعد الفلاتر) مع تسميات عربية، وPDF بتنسيق RTL باسم الشركة.

## سير عمل موصى به خطوة بخطوة

مثال: توظيف مندوب مبيعات جديد اسمه «سامي» لفرع عدن:

1. القائمة الجانبية ← الإعدادات ← الأدوار. الأدوار المدمجة تكفي عادة — دور `sales_rep` جاهز. (إن أردت تخصيصاً: انسخ `sales_rep`، أضف `crm.create` مثلاً، واحفظ.)
2. القائمة الجانبية ← الإعدادات ← المستخدمون ← **«مستخدم جديد»**.
3. اكتب اسم المستخدم `sami`، الاسم الكامل، الهاتف، البريد.
4. اختر الدور **«مندوب مبيعات»** والفرع **«فرع عدن»**.
5. اترك «حساب نشط» محدداً واحفظ.
6. أعطِ سامي كلمة المرور الابتدائية؛ وعند أول خلاف استخدم **إعادة تعيين كلمة المرور**.
7. لاحقاً، راقب نشاطه من **سجل التدقيق** بعد الفلترة على اسمه: دخوله، فواتيره، أي تعديل.

## قواعد مهمة

- الصلاحية تُفحص عند كل عملية حساسة على الخادم، لا عند الواجهة فقط.
- `module.own` يفلتر القوائم للمستخدم نفسه، لكنه لا يمنع إنشاء مستندات جديدة.
- تعديل صلاحيات دور يأثر **فوراً** على كل من يحمل الدور (الجلسات تُحدَّث).
- كل عملية في صفحات المستخدمين والأدوار (إنشاء/تعديل/حذف/إعادة كلمة مرور/تفعيل) تُسجَّل في سجل التدقيق.
- المستخدم المعطَّل يُمنع من الدخول فوراً، ويُرفض استئناف جلسته القديمة.

## أخطاء شائعة وحلولها

| الرسالة أو الملاحظة | السبب | الحل |
|---|---|---|
| لا أرى زر «مستخدم جديد» | صلاحية `settings.edit` ناقصة | اطلب من `super_admin` منحها لدورك |
| أزرار الحذف/التعطيل رمادية على مستخدم معيّن | هذا حسابك الحالي | استخدم حساباً آخر لإدارة حسابك، أو اطلب من مدير أعلى |
| «للقراءة فقط» في نافذة الدور | الدور نظامي (isSystem) | اضغط «نسخ» وأنشئ دوراً مخصصاً |
| كتبت مساراً في المتصفح ورجعت للوحة التحكم | صلاحية الوحدة ناقصة — الحماية فعّالة | اطلب الصلاحية المناسبة (`module.view` أو `module.own`) |
| لا يرى المندوب فواتير زملائه | هذا سلوك `sales.own` المقصود | أعطه `sales.view` للعرض الكامل إذا لزم |
| شاشة «ليس لديك صلاحية عرض سجل التدقيق» | `settings.audit_log` ناقصة | تُمنح للإدارة فقط — راجع مدير النظام |

## نصائح

- ابدأ بالأدوار المدمجة؛ أنشئ أدواراً مخصصة فقط عند حاجة حقيقية — قلّة الأدوار تسهّل المراجعة.
- استخدم «نسخ» دائماً بدل بناء دور من الصفر.
- راجع سجل التدقيق أسبوعياً وفلتر على الحركات «حذف» و«إعادة كلمة مرور».
- عند مغادرة موظف: **عطّل** الحساب بدل حذفه — يحفظ تاريخ المستندات المرتبطة به.
