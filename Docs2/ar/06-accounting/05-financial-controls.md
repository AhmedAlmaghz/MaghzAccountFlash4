# الضوابط المالية وتقييد العمليات — دليل الاستخدام

> كيف يمنع النظام الأخطاء والتلاعب في العمليات المالية: فصل الصلاحيات، الترحيل الذري، نهائية المُرحَّل، قفل الفترات، سجل التدقيق، وبوابات المخزون والنقدية — وفق أفضل الممارسات العالمية.

## نظرة عامة

كل عملية مالية في النظام تمر بثلاث بوابات قبل أن تؤثر في الدفاتر: **من يُسمح له** (الصلاحيات)، **هل العملية سليمة محاسبياً** (التوازن والتحقق)، **وهل تُسجَّل وتُقفل** (التدقيق والفترات). هذا الفصل يجمع القواعد المبعثرة في فصول الوحدات في خريطة حوكمة واحدة، ويشرحها بأمثلة تطبيقية.

تجد تطبيقات هذه الضوابط في: **القائمة الجانبية ← المحاسبة** (`/accounting`)، و**القائمة الجانبية ← المستخدمون والأدوار** (`/users` و`/roles`)، و**المحاسبة ← الإقفال السنوي** (`/accounting/year-end`)، و**سجل التدقيق** (`/audit-logs`).

## الوصول والصلاحيات

| الفعل | الصلاحية |
|---|---|
| عرض الشجرة والقيود والسندات والتقارير | `accounting.view` |
| إنشاء حساب/قيد/سند (مسودة) | `accounting.create` |
| تعديل/حذف المسودات فقط | `accounting.edit` / `accounting.delete` |
| الترحيل (تثبيت الأثر المالي) | `accounting.post` |
| الإقفال السنوي وإهلاك الأصول | `accounting.post` (نفس صلاحية الترحيل) |
| عرض مستندات المستخدم نفسه فقط | `accounting.own` |

> **القاعدة الذهبية:** إخفاء عنصر من القائمة الجانبية **ليس** حماية. كل مسار محمي على مستوى المسار (`PermissionRoute`) — الوصول المباشر بالرابط لصفحة بلا صلاحية يُعاد توجيهه للرئيسية.

### فصل المهام (SoD) — أفضل ممارسة عالمية

| الدور | الوصول المحاسبي |
|---|---|
| `super_admin` / `admin` | كل شيء (بما فيه الإعدادات والأدوار) |
| `manager` (مدير عام) | عرض/إنشاء/تعديل/**ترحيل** |
| `accountant` (محاسب) | عرض/إنشاء/تعديل/**ترحيل** — التشغيل اليومي |
| `sales_rep` (مندوب مبيعات) | لا وصول للمحاسبة — ينشئ فواتير مسودة فقط عبر `sales.create` |
| `viewer` (مطالع) | عرض فقط |

التطبيق العملي للفصل: المندوب **ينشئ** الفاتورة مسودة، والمحاسب **يرحّلها**، والمدير **يقفل** الفترة — فلا يجمع شخص واحد الإنشاء والاعتماد والقفل.

## خريطة الضوابط — أين يُقيَّد كل خطر؟

| الخطر | الضابط | أين يطبَّق في الكود |
|---|---|---|
| قيد غير متوازن | الحفظ كـ«مُرحّل» محجوب إلا إذا المدين = الدائن والمبلغ > 0 (سماحية 0.01) | `accounting/api.ts` — إنشاء/تعديل/ترحيل القيد |
| تعديل التاريخ بعد الترحيل | المُرحَّل غير قابل للتعديل ولا الحذف — التصحيح بقيد جديد أو عكسي | نفس الملف + `reversal.ts` |
| ترحيل مزدوج متزامن | قلب الحالة مشروط (`AND status='draft'`) + تحقق من `RETURNING id` — السباق يُرجع خطأ صريحاً | `postTransaction` |
| ترحيل في فترة مقفلة | فحص `assertPeriodOpen` في 8 مسارات ترحيل (قيود، سندات، فواتير ومردودات المبيعات والمشتريات، رواتب، POS) | `src/modules/tax/engine.ts` |
| ترحيل في سنة مقفلة | فحص `assertAccountingPeriodOpen` — السنة المغلقة (`accounting_periods.status='closed'`) ترفض أي ترحيل جديد | `src/modules/accounting/yearEnd.ts` |
| بيع من مخزون فارغ | بوابة `checkStockSufficiency` — **المنع هو الافتراضي**؛ السماح الاستثنائي يُوثَّق عبر `auditOverride` | `src/core/utils/stockPolicy.ts` |
| دفع من خزينة فارغة | فحص `getCashBoxGlBalance` (رصيد الدفتر من `SUM(je)`) عند إنشاء السند مرحّلاً مباشرة وعند الترحيل اللاحق | نفس الملف عبر `accounting/api.ts` |
| تجاوز الحد الائتماني للعميل | فحص الحد عند الترحيل — القيمة 0 تعني بلا حد | نفس البوابة |
| تكرار قيد/فاتورة/سند | حارس التكرار: مطابقة تامة ← **حظر**، تقارب عالٍ ← تحذير مع نسبة التشابه | صفحات القيود والفواتير والسندات |
| كتابة وكيل ذكي بلا مراجعة | `fail-closed`: أي أداة كتابة تتطلب بطاقة موافقة تعرض الملخص قبل التنفيذ | `src/modules/ai` (المحرك) |
| فقدان أثر التعديل | سجل التدقيق `audit_logs`: كل إنشاء/تعديل/حذف/ترحيل/عكس مع المستخدم والوقت والقيم | `/audit-logs` |

## دورة حياة المستند المالي

| الحالة | المعنى | ماذا يمكن فعله فيها |
|---|---|---|
| **مسودة** (Draft) | لا أثر مالي — غائبة عن كل التقارير | تعديل، حذف، **ترحيل**، طباعة |
| **مُرحَّل** (Posted) | قيد مولَّد ومؤثر — داخل في كل التقارير | قراءة وطباعة و**عكس** فقط |
| **معكوس** (Reversed) | للسندات: عُكس بقيد مرآة وقلب الحالة | قراءة فقط — لا ترحيل ثانٍ |
| **ملغى** (Cancelled) | مسودة أُسقطت قبل الترحيل | قراءة فقط |
| **مغلقة فترته/سنته** | الفترة أو السنة أُقفلت | لا ترحيل جديد بتاريخ داخلها إطلاقاً |

## سير عمل خطوة بخطوة — مثال رقمي كامل (بيع نقدي بضريبة)

العملية: بيع نقدي 100,000 ر.ي + ضريبة 15% = **115,000**، التكلفة المجمدة للسطر 60,000، الصندوق `11101`، الإيراد `41101`، ضريبة المخرجات `21301`، تكلفة المبيعات `51101`، المخزون `11301`.

1. القائمة الجانبية ← المبيعات ← فواتير المبيعات ← **«فاتورة جديدة»** (تحتاج `sales.create`).
2. العميل: العميل النقدي الافتراضي (Walk-in)، نوع الدفع: **نقدي**، الخزينة: صندوق الرئيسي (بلا حساب دفتري ← الترحيل سيرفض لاحقاً — اختر صندوقاً مربوطاً بحساب).
3. السطر: صنف بسعر 100,000، الكمية 1. النظام يجمد `unit_cost` وقت الترحيل لا وقت الإدخال.
4. احفظ **مسودة** — لا قيد بعد، ولا أثر في الذمم (النقدي لا يمس رصيد العميل).
5. اضغط **«ترحيل»** (تحتاج `sales.post` أو `accounting.post` حسب الإعداد). تنفذ البوابات بالترتيب:
   - الفترة الضريبية والسنة المحاسبية مفتوحتان لتاريخ الفاتورة؟
   - المخزون كافٍ (أو تجاوز مُدقَّق)؟
   - رصيد الخزينة الدفتري يغطي (للمدفوعات)؟
6. عند النجاح تُنفَّذ **ذرياً** (معاملة واحدة — الكل أو لا شيء):

| القيد | الحساب | مدين (ر.ي) | دائن (ر.ي) |
|---|---|---:|---:|
| قيد البيع | الصندوق `11101` | 115,000 | |
| | إيراد المبيعات `41101` | | 100,000 |
| | ضريبة المخرجات `21301` | | 15,000 |
| قيد التكلفة (`-COGS`) | تكلفة المبيعات `51101` | 60,000 | |
| | المخزون `11301` | | 60,000 |

7. النتيجة: `paid_amount = 115,000` والحالة **مدفوعة** (`paid`)، ورصيد العميل **لم يتغير** (نقدي)، والمخزون نقص بالكمية المباعة.

### ماذا لو أخطأت بعد الترحيل؟

اكتشفت أن السعر الصحيح 90,000 + ضريبة. الفاتورة مُرحّلة — التعديل والحذف **معطلان**. المسار الصحيح:

1. أنشئ **مرتجع مبيعات** بالفرق (أو بالكامل ثم فاتورة صحيحة) — المرتجع يعكس الإيراد والضريبة على `21301` والتكلفة فعلياً من `unit_cost` المجمدة.
2. للقيود اليدوية: أنشئ **قيداً عكسياً** (`REV-` + المرجع الأصلي) يعكس المدين والدائن — الأصل يبقى مُرحّلاً والتقارير (مجموع المرجّح) تصفّر الأثر.
3. للسندات: **العكس** يولّد مرآة الأرجل الفعلية ويقلب حالة السند إلى `reversed` — لا عكس مزدوج (الحارس يرفض `REV-` موجوداً).

## قواعد مهمة — ملخص سريع

| القاعدة | التفصيل |
|---|---|
| `SUM(je)` مصدر الحقيقة الوحيد | الأرصدة تُحسب من القيود المرحّلة؛ عمود `balance` مرآة عرض لا تُجمع مع القيود |
| المُرحَّل نهائي | لا تعديل ولا حذف — عكس فقط، والعكس المزدوج مستحيل (حارس `REV-` + عكس الباقي فقط) |
| الدفتر بالعملة الأساسية | أي مستند أجنبي يُرحَّل بمبالغ الأساس (`base_*` المحسوبة على الخادم)؛ الفرق قيد فروق مستقل |
| الضريبة فصل لا حساب واحد | المخرجات `21301` دائنة، المدخلات `21302` مدينة (contra-liability) — الإقرار من أرجل القيود للفترة |
| التكلفة مجمدة وقت البيع | `unit_cost` تُخزَّن عند الترحيل؛ المردود يعكس **التكلفة الفعلية** لا نسبة تقديرية |
| القفل عند الترحيل لا الإدخال | المسودات حرة بأي تاريخ؛ لحظة الترحيل تفحص الفترة الضريبية والسنة المحاسبية |
| المنع افتراضياً | أي سياسة مخزون/ائتمان/خزينة غير مضبوطة = **منع** — التجاوز يُوثَّق في التدقيق |
| الموافقة قبل الكتابة الآلية | الوكيل الذكي يعرض بطاقة بملخص العملية؛ بلا موافقة لا تنفيذ (fail-closed) |

## أخطاء شائعة وحلولها

| الرسالة | السبب | الحل |
|---|---|---|
| «الفترة الضريبية مغلقة» | تاريخ المستند داخل فترة `closed/filed` | غيّر تاريخ الترحيل لفترة مفتوحة، أو أعد فتح الفترة بصلاحية مخولة |
| «السنة المالية مقفلة» | `accounting_periods.status='closed'` للسنة | الترحيل في السنة المقفلة ممنوع إطلاقاً — سجّل في السنة المفتوحة |
| «المخزون غير كافٍ» | البوابة رفضت البيع تحت الصفر | خفّض الكمية، أو حوّل من مستودع آخر، أو اطلب تجاوزاً مُدقَّقاً من مخول |
| «رصيد الخزينة لا يغطي» | الدفتر (`SUM(je)`) أقل من المبلغ | غدِّ الخزينة بسند قبض أولاً، أو غيّر الخزينة |
| «تجاوز الحد الائتماني» | مستحق العميل + الجديد فوق الحد | حصّل دفعة أولاً، أو ارفع الحد من بطاقة العميل |
| «قيد غير متوازن» | المدين ≠ الدائن | ساوِ المجموعين (سماحية 0.01 للتقريب) |
| «عُكس مسبقاً» | مرجع `REV-` موجود | لا عكس ثانٍ — راجع القيد العكسي الموجود |
| «الفاتورة مُرحّلة — التعديل معطل» | حماية المُرحَّل | أنشئ مرتجعاً بالفرق بدل التعديل |

## نصائح

- راجع فلتر «مسودة» نهاية كل يوم: المسودات غير مرئية في أي تقرير مالي.
- قبل أي ترحيل كبير تحقق من مؤشر «متوازنة» في المركز المالي.
- لا تدخل يدوياً ما تولّده الوحدات: فاتورة مُرحّلة أنشأت قيدها — القيد اليدوي المكرر تضخيم.
- أي تجاوز مُدقَّق (بيع تحت الصفر، دفع فوق الرصيد) يجب أن يُراجَع أسبوعياً من سجل التدقيق.
- سنة مقفلة = أرشيف: أي تصحيح يخصها يُسجَّل في السنة المفتوحة بقيد تسوية مع إشارة مرجعية.
