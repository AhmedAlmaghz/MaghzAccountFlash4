# وحدة المحاسبة — دليل الاستخدام

> قلب النظام المحاسبي: شجرة حسابات متوافقة مع المعايير المزدوجة، قيود يومية، سندات قبض وصرف، والتقارير المالية الأربعة.

## نظرة عامة

وحدة المحاسبة هي المرجع الذي تتدفق إليه كل الحركات من بقية الوحدات: فاتورة مبيعات تُرحَّل فتنشئ قيداً، سند قبض يخفض رصيد عميل، فاتورة مشتريات ترفع ذمماً دائنة. إذا كنت جديداً على النظام، اتبع خريطة القراءة أدناه بترتيبها.

**المسار:** القائمة الجانبية ← **المحاسبة**. الصفحة الأم `/accounting` تعرض بطاقات التنقل لكل الشاشات الفرعية:

| الشاشة | المسار | الغرض |
|---|---|---|
| شجرة الحسابات | `/accounting/chart` | بنية الحسابات الهرمية وإدارتها |
| قيود اليومية | `/accounting/journal` | إدخال القيود اليدوية وترحيلها |
| سندات القبض | `/accounting/receipt-vouchers` | الأموال الواردة من العملاء |
| سندات الصرف | `/accounting/payment-vouchers` | الأموال الخارجة للموردين والمصروفات |
| دفتر الحساب | `/accounting/ledger` | حركات حساب واحد برصيد متجدد |
| ميزان المراجعة | `/accounting/trial` | أرصدة كل الحسابات حتى تاريخ |
| قائمة المركز المالي | `/accounting/balance` | أصول مقابل التزامات وحقوق ملكية |
| قائمة الدخل | `/accounting/profit` | إيرادات ومصروفات وصافي ربح الفترة |
| قائمة التدفقات النقدية | `/accounting/cashflow` | حركة النقد بالطريقة غير المباشرة |

## «أبدأ من أين؟» — خريطة القراءة

1. **شجرة الحسابات أولاً** (`01-chart-of-accounts.md`): افهم البنية الهرمية والأنواع الخمسة والطبيعة المدينة/الدائنة. لا معنى لأي شيء آخر قبل ذلك — كل قيد وسند يقع على حسابات من الشجرة.
2. **قيود اليومية ثانياً** (`02-journal-entries.md`): جوهر المحاسبة المزدوجة. تعلّم محرر الأسطر وفحص التوازن وقواعد الترحيل — فهي نفسها مطبقة داخل السندات والفواتير.
3. **سندات القبض والصرف ثالثاً** (`03-vouchers.md`): الحركة اليومية الأكثر تكراراً على الصندوق، وهي في جوهرها قيود جاهزة تُبنى لك تلقائياً.
4. **التقارير المالية أخيراً** (`04-financial-reports.md`): دفتر الحساب وميزان المراجعة والمركز المالي وقائمة الدخل والتدفقات النقدية — ثمرة ما سبق.

## الوصول والصلاحيات

كل شاشات الوحدة تحتاج `accounting.view` للعرض. بقية الأفعال منفصلة:

| الصلاحية | ما تفتحه |
|---|---|
| `accounting.view` | عرض الشجرة والقيود والسندات وكل التقارير المالية |
| `accounting.create` | إنشاء حساب جديد، قيد جديد، سند جديد |
| `accounting.edit` | تعديل المسودات (المُرحَّل محجوب للجميع) |
| `accounting.delete` | حذف المسودات |
| `accounting.post` | **الترحيل** — تحويل مسودة إلى قيد مؤثر ماليًا (يُنشئ القيد ويحدّث الأرصدة) |
| `accounting.own` | «مستنداتي فقط» — تُفلتر القوائم لقيود وسندات المستخدم نفسه |

**ماذا يرى كل دور:**

| الدور | الوصول |
|---|---|
| `super_admin` / `admin` | كل شيء |
| `manager` (مدير عام) | عرض/إنشاء/تعديل/**ترحيل** |
| `accountant` (محاسب) | عرض/إنشاء/تعديل/**ترحيل** — الدور المخصص للمحاسبة اليومية |
| `sales_rep` (مندوب مبيعات) | لا وصول للمحاسبة أصلاً |
| `viewer` (مطالع) | عرض فقط — بلا إضافة أو تعديل أو ترحيل |

## المفاهيم المحاسبية المطبقة في الوحدة

- **المحاسبة المزدوجة:** كل حركة لها طرفان متوازنان — مجموع المدين = مجموع الدائن. النظام يفرض هذا على مستوى الحفظ والترحيل.
- **مسودة ← ترحيل:** كل مستند محاسبي (قيد أو سند) يُنشأ **مسودة** قابلة للتعديل والحذف، ثم **يُرحَّل** فيصبح نهائياً غير قابل للتعديل وينعكس في التقارير.
- **القيود المرحّلة فقط تُحتسب:** كل التقارير المالية (ميزان المراجعة، المركز المالي، قائمة الدخل، دفتر الحساب) تقرأ من القيود **المرحّلة** حصراً.
- **الرصيد الافتتاحي (Opening Balance):** يُدخل من شجرة الحسابات كقيد متوازن عبر حساب حقوق ملكية الافتتاح، فتظهر الأرصدة الافتتاحية في التقارير تلقائياً دون معالجة خاصة.
- **سجل التدقيق:** كل إنشاء وتعديل وحذف وترحيل يُسجَّل في سجل التدقيق مع المستخدم والوقت والقيم القديمة/الجديدة.

## سير الحركة بين الوحدات — أين تظهر حركاتك؟

تقرير غريب في المحاسبة سببه غالباً مستند من وحدة أخرى. جدول التتبع السريع:

| إذا رأيت... | فمصدره غالباً | ولإصلاحه |
|---|---|---|
| رصيد عميل لا يطابق كشحه | فاتورة مبيعات مُرحّلة أو سند قبض | راجع فواتير المبيعات وسندات القبض للعميل |
| رصيد مورد ارتفع فجأة | فاتورة مشتريات مُرحّلة | راجع فواتير المشتريات |
| قيد لم تدخله يدوياً | ولّدته وحدة: مبيعات/مشتريات/POS/تصنيع/رواتب | راجع مستندات الوحدة المصدر — لا تحاول تعديل قيدها |
| مخزون بقيمة مختلفة عمّا تتوقع | حركات مخزون وتسويات | راجع المخازن ← الحركات والتسويات |

## مصطلحات ستقابلك في الوحدة

| المصطلح | المعنى هنا |
|---|---|
| **مسودة** | مستند غير مُرحّل — لا يؤثر في الأرصدة ولا التقارير |
| **ترحيل** | تثبيت المستند: يُنشئ القيد المحاسبي ويحدّث الأرصدة ويقيّد التعديل |
| **الرصيد المتجدد** | رصيد تراكمي في دفتر الحساب: كل صف يعرض الرصيد بعده مباشرة |
| **حتى تاريخ** | تقرير لحظي يتراكم من بداية الدفاتر حتى ذلك اليوم |
| **الرصيد الافتتاحي** | رصيد الحساب عند بداية استخدام النظام — يُرحَّل عبر حساب حقوق ملكية الافتتاح |
| **سماحية 0.01** | هامش التسامح في مقارنات التوازن لامتصاص فروق التقريب |

## ماذا تجد جاهزاً عند أول تشغيل؟

النظام لا يبدأ فارغاً — **البيانات الافتراضية** تُنشأ تلقائياً:

| العنصر الجاهز | التفصيل |
|---|---|
| شجرة حسابات كاملة | خمسة أنواع رئيسية بحساباتها الجماعية والتفصيلية الأساسية (الصندوق، البنك، الذمم، رأس المال، الإيرادات، المصروفات...) |
| حسابات النظام | حساب حقوق ملكية الافتتاح للرصيد الافتتاحي، وحسابات ربط الوحدات |
| تسلسلات المستندات | ترقيم تلقائي للقيود والسندات دون تدخل يدوي |
| بيانات تجريبية (اختيارية) | قيود وسندات وفواتير للتجربة — تُحذف قبل التشغيل الفعلي |

## قبل التشغيل الفعلي — قائمة تحقق المحاسب

1. راجع شجرة الحسابات الافتراضية وفعّل ما ينشاطك وأضف حساباتك التفصيلية الخاصة.
2. أدخل **الرصيد الافتتاحي** لكل حساب تفصيلي (نقدية، بنوك، مخزون، ذمم، أصول ثابتة...) — يُرحَّل تلقائياً عبر حقوق ملكية الافتتاح.
3. تأكد من ظهور مؤشر **«متوازنة»** في قائمة المركز المالي بعد الافتتاحيات.
4. جرّب سند قبض وسند صرف تجريبيين على حسابات وهمية ثم احذفهما قبل الدخول الفعلي.
5. اطلع على ميزان المراجعة — مجموع المدين يجب أن يساوي الدائن من اللحظة الأولى.

## نصائح

- ابدأ يومك من صفحة المحاسبة الرئيسية `/accounting` — البطاقات تنقلك مباشرة لما تحتاج.
- الأخطاء الجسيمة في القيود تُصحَّح بقيد **عكسي** جديد وليس بتعديل — لأن المُرحَّل غير قابل للتعديل.
- راقب مؤشر التوازن في قائمة المركز المالي بعد كل دفعة ترحيل كبيرة؛ «متوازنة» تعني أن الأصول = الالتزامات + حقوق الملكية فعلاً.

## أسئلة يكثر طرحها

| السؤال | الجواب |
|---|---|
| هل يمكنني تعديل قيد مُرحّل؟ | لا — بحكم تصميم الوحدة. أنشئ قيداً عكسياً وسجّله |
| هل تظهر المسودات في التقارير؟ | لا — كل التقارير تقرأ من القيود المرحّلة حصراً |
| لماذا رصيد الحساب الجماعي لا أعدّله؟ | لأنه محسوب آلياً كمجموع أبنائه — عدّل التفصيلي عبر القيود |
| أين أرى رصيد عميل معين؟ | كشف حساب العميل في مركز التقارير، أو دفتر الحساب لحساب الذمم المدينة |
| دخلت رصيداً افتتاحياً ولم يظهر في التقرير | تأكد أن قيد الافتتاح المولَّد تم ترحيله وليس مسودة |
| كيف أصدّر تقريراً؟ | زر Excel أو PDF أعلى كل تقرير — يصدّر ما تعرضه حالياً بفلاتره |
| هل سند القبض قيد منفصل عن القيد الذي أنشأته؟ | لا — السند عند الترحيل **يولّد** قيده تلقائياً؛ لا تدخّله يدوياً |
| من يملك صلاحية الترحيل في شركتي؟ | من يملك `accounting.post` — عادة المدير العام والمحاسب (راجع صفحة الأدوار) |
| غيّرت تاريخ التقرير ولم تتغير الأرقام | تأكد أن فترتي المقارنة تحويان قيوداً مرحّلة فعلاً — الفترة الفارغة تعرض أصفاراً |
| هل يمكن ربط المحاسبة بأكثر من عملة؟ | نعم — السندات تقبل عملة وسعر صرف، ويُحفظ المعادل بالعملة الأساسية (راجع قسم تعدد العملات) |
