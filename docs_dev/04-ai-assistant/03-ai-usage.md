# استخدام الوكيل الذكي يومياً

> أمثلة عملية جاهزة للنسخ — كلها بالعربية الطبيعية

---

## البحث: «دور على...»

المساعد يبحث بضبابية عربية متسامحة مع الإملاء:

```
«دور لي على عميل اسمه ابو محمد»
«أريني الموردين اللي رصيدهم فوق مليون»
«فيه سند قبض باسم النور؟»
«دور على منتج فيه كلمة أرز»
«ابحث عن حساب مصروف انترنت»     ← يفهم حتى لو الحساب اسمه "مصروفات الإنترنت والاتصالات"
```

النتيجة تظهر كبطاقة أداة قابلة للتوسيع — تعرض أفضل المطابقات بنسب تشابه.

---

## القراءة والملخصات: «كم... / أعطني...»

```
«كم مبيعات الشهر؟»
«اعطني ملخص مبيعات هذا الشهر مقارنة بالشهر الماضي»
«كم صافي ربح الربع الأول؟»
«وش وضع المخزون؟ ايش اللي ناقص؟»
«كم يستحق علينا للموردين؟»
«ميزان المراجعة للشهر الماضي»
```

تأتي أرقام حقيقية من قاعدة بياناتك — جداول منسقة بMarkdown وأرقام عريضة.

## المتابعات اليومية (أداة المتابعات الذكية)

```
«ما متابعاتي العاجلة اليوم؟»
«ايش المهام المتأخرة عندي؟»
«مين العملاء اللي ما تواصلنا معهم من فترة؟»
```

يجمع لك: المهام المتأخرة + المستحقة اليوم + **الفرص التي تجاوزت تاريخ الإغلاق** + العملاء بلا تواصل ≥N يوم — مرتبة بالأولوية.

## إنشاء المستندات ⭐ (بموافقتك)

### فاتورة مبيعات
```
«سجل فاتورة مبيعات لعميل بقالة النور:
 خمسة كيس أرز بسمتي بسعر خمسة آلاف وخمسمئة
 نقدي من الصندوق الرئيسي»
```
**ماذا يحدث:**
1. يبحث عن العميل (ضبابياً) والمنتج والخزينة — ويعرض ما وجد
2. **بطاقة موافقة كهرمانية**: عدد الأصناف + **الإجمالي التقديري قبل الضريبة**
3. «موافقة» ← فاتورة مسودة بنقاطها... «رحّلها» ← قيد كامل وحركة مخزون

> 💡 الوكيل يحترم نوع الدفع: «نقدي» ← يطلب الخزينة ويقيّد عليها؛ «آجل» ← على حساب العميل. وطرق السندات: «نقد»/«كاش» = cash، «حوالة»/«محفظة» = bank، «شيك» = check + رقمه.

### سند صرف مصروف عام
```
«سجل سند صرف مصروف كهرباء 45 ألف من خزينة المكتب»
```
يبحث عن حساب المصروف والخزينة ← موافقة ← سند مرحّل (مدين مصروف / دائن خزينة).

### عميل جديد + فاتورة بخط واحد
```
«أنشئ عميل جديد اسمه مؤسسة الفجر ثم سجل له فاتورة...»
```

### قيد يومي متوازن
```
«قيد يومية: من حساب الصندوق مليون إلى حساب رأس المال»
```

## المعالجات المركبة (Wizard)

| اطلب | ماذا يفعل |
|---|---|
| «اصنع وترحّل فاتورة شراء من مورد X...» | إنشاء + ترحيل بخطوة واحدة |
| «جهّز وترحّل رواتب هذا الشهر» | **معاينة ← إنشاء مسير ← ترحيل** — وإن فشل الترحيل يحذف المسيرة تلقائياً (تراجع حقيقي) |
| «حوّل المحتمل سالم لعميل وافتح فرصة» | تحويل ذرّي + فرصة أولى بقيمته التقديرية |
| «أهّل المحتمل أحمد وافتح فرصة ومهمة متابعة» | تأهيل + فرصة + مهمة بعد 3 أيام — بتراجع تعويضي عند أي فشل |
| «انقل 50 كرتونة من مستودع الرئيسي للفرع» | تحويل مخزون كامل |

## التصنيع بالصوت أو النص

```
«كم ممكن أنتج من شجرة أرز معبأ؟»        ← فحص توفر الخامات وأقصى قابل للإنتاج
«ابدأ أمر التشغيل رقم اثنين»            ← يصرف الخامات (يفشل بتقرير نقص إن لم تكفِ)
«أكمل أمر التشغيل الثاني، أنتجنا 9 بس بدل 10»  ← إكمال بكمية فعلية وحساب الفرق
```

## التنقل

```
«افتح صفحة الفواتير»
«ودّيني لتقرير أعمار الذمم»
«ايش الصفحات اللي أقدر أفتحها؟»
```
والرقائق تحت آخر رد تعرض اقتراح «انتقال» ذكي مبني على آخر أداة نُفذت.

## عادات الاستخدام الجيدة

| افعل | لماذا |
|---|---|
| اذكر اسم الكيان بدقة معقولة | الضبابي يسامح، لكن الوضوح أسرع |
| حدد نوع الدفع والمبلغ والعملة | يقلل أسئلة المساعد |
| راجع بطاقة الموافقة دائماً | هي عقدك مع المساعد — ما وافق عليه فقط يُنفذ |
| استخدم «على الحساب» بوضوح للسندات | «دفعة على الحساب بلا ربط بفاتورة» سلوك مختلف عن التطبيق |
| لما يخطئ اسم كيان، صححه ببساطة | «لا أقصد النور للمواد، أقصد بقالة النور» — يعيد البحث |
| اطلب الأرقام لا الاستنتاجات | «كم المبيعات؟» أدق من «هل أبيع جيداً؟» |

## ماذا يرفض المساعد ولماذا؟

| الطلب | الرد |
|---|---|
| حذف فاتورة مرحّلة | يشرح أن النظام يحمي المرحّل ويقترح قيداً عكسياً |
| إنشاء مسير رواتب لنفس شهر موجود | يشرح قاعدة الفترة الواحدة ويعرض المسير الحالي |
| اعتماد إجازة تتجاوز الرصيد | يعرض الرصيد والمتبقي — لن يتجاوز الحارس الخدمي |
| رجوع فرصة لمرحلة سابقة | آلة الحالات للأمام فقط — يشرح |
| رقم مستند بلا أداة | حارس الهلوسة — لن يدّعي تنفيزاً لم يفعله |

هذه ليست عيوباً — بل **نفس حوارس الشاشات** تطبق عليه (كل الأدوات تستدعي نفس APIs).
