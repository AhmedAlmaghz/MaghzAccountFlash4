# كشوف الحسابات وأعمار الديون

> المرجع المالي للعلاقات مع العملاء والموردين — **الأرصدة الافتتاحية مدمجة دائماً**

---

## الفلسفة: الرصيد الكامل بلا استثناء

كل كشف وكل تقرير أعمار في النظام يتبع المبدأ المحاسبي العالمي:

> **رصيد آخر سطر = الرصيد الكامل** (افتتاحي + كل الحركة)

- كل كشف يبدأ بسطر **«رصيد افتتاحي»** (يحمل تاريخه، أو 1900-01-01 إن كان غير مؤرخ)
- الفلترة بالتاريخ **لا تفقد الرصيد**: ما قبل الفترة يُجمع في سطر افتتاحي أول
- الفواتير الملغاة مستثناة من كل الحسابات

---

## كشف حساب عميل (مفرد)

**الوصول**: المبيعات ← العملاء ← تفاصيل العميل — أو أداة الوكيل `sales.get_customer_statement`

### بنية الكشف
| # | السطر | النوع |
|---|---|---|
| 0 | **الرصيد الافتتاحي** (مميز بشارة) | بداية |
| + | فواتير مبيعات مرحّلة | **مدين** (يزيد ماله علينا) |
| − | سندات قبض مرحّلة (مربوطة أو على الحساب) | **دائن** |
| − | مردودات بيع مرحّلة | دائن |

**الرصيد الجاري** يتراكم سطراً بسطر — عمود الترتيب يضمن التسلسل الزمني.

### الفلترة
من/إلى تاريخ — مع سطر افتتاحي يحمل رصيد ما قبل الفترة (لا يضيع منه شيء).

## تقرير أعمار ذمم العملاء (AR Aging) — على مستوى الشركة

**المسار**: `/reports/customer-statement` — أقوى عرض لما يجب تحصيله.

### الفلاتر
من/إلى تاريخ + **تاريخ مرجعي للأعمار (as of)** — الأعمار تُحسب لحظة هذا التاريخ.

### بطاقات KPI (5)
| البطاقة | اللون | المعنى |
|---|---|---|
| **إجمالي المستحق** | — | كل ما عليك تحصيله |
| **0-30 يوم** | 🟢 أخضر | حديث — طبيعي |
| **31-60 يوم** | 🟡 كهرماني | انتبه |
| **61-90 يوم** | 🟠 برتقالي | ضغط تحصيل |
| **+90 يوم** | 🔴 أحمر | خطر — بادر بالمعالجة (هنا يقع كل افتتاحي غير مؤرخ) |

كل شريحة تعرض أيضاً **عدد العملاء** فيها.

### عمود الأعمار في الجدول
لكل عميل: الهاتف + الشرائح الأربع + الإجمالي + عدد الفواتير — صورة كاملة لمن يدين لك وبتاريخ استحقاقه.

### من أين تأتي بيانات الشريحة؟
- الفاتورة تدخل شريحة **الأيام منذ استحقاقها** (`due_date` — ليس تاريخ الإصدار)
- **الفواتير المدفوعة بالكامل مستثناة** (`outstanding > 0` فقط)
- **الأرصدة الافتتاحية تدخل** بتاريخها (غير المؤرخ = +90)

## كشف حساب وأعمار الموردين (AP)

**المسار**: `/reports/supplier-statement` — مرآة العميل للجانب الشراء.

### كشف مورد (مفرد)
استعلام موحد واحد:
- **سطر افتتاحي** (ما عليه لنا قبل النظام)
- فواتير مشتريات مرحّلة = **دائن** (ما ندين به له)
- سندات صرف + مردودات شراء = **مدين** (ما سددناه/عدلناه)

### بطاقات الأعمار الخمس + الجدول
نفس شرائح AR (0-30/31-60/61-90/+90) لما **نحن مدينون به** — أساس إدارة الدفعات:
> 💡 **استخدام عملي**: ادفع شريحة +90 أولاً (تجنب توقف التوريد)، ثم 61-90 — الجدول يرتب لك أولويات الدفع لكل مورد.

### إجمالي AP على مستوى الشركة
- بطاقة «مستحقات الموردين» في **لوحة التحكم**
- رقم **التدفق النقدي** (فواتير غير مسددة + مجموع الافتتاحيات)
- أداة الوكيل `purchases.get_ap_aging_total`

## حالات استخدام عملية

| الموقف | ماذا تفتح |
|---|---|
| عميل يسأل «كم لي عليك؟» | كشف حساب العميل + أرسله PDF |
| اجتماع تحصيل أسبوعي | تقرير أعمار AR — رتب بالشريحة +90 |
| تخطيط دفعات نهاية الشهر | تقرير أعمار AP |
| عميل جديد بدين قديم | سجل **رصيد افتتاحي بتاريخه** عند إنشائه — سيدخل الأعمار في شريحته الصحيحة |
| راجع حساباً مشبوهاً | دفتر الأستاذ لحساب العميل في الشجرة |

---

## ملاحظة تقنية للدقة

- **السندات غير المربوطة** بفاتورة («على الحساب») تدخل الكشف كدائن وتخفض الرصيد — الفواتير تبقى مستحقة حتى يُربط سند بها (الربط من شاشة السند)
- **سند مرحّل لا يُحذف** إن كان مربوطاً بفاتورة — الاتساق محروس حتى لو حاولت
- الفواتير النقدية لا تدخل الأعمار (مسددة بطبيعتها)
