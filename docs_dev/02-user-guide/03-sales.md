## فواتير المبيعات

**المسار**: `/sales/invoices` — قلب دورة الإيراد.

### شاشة القائمة
- **فلاتر**: الحالة (مسودة/مرحّلة/مدفوعة جزئياً/مدفوعة/ملغاة) + العميل + بحث + «سجلاتي فقط»
- **بطاقات إحصائية**: إجمالي الفواتير النشطة، المستحق، المرحّلة (تستثني الملغاة)
- **ترقيم من الخادم** — يتعامل مع آلاف الفواتير بسلاسة
- أزرار كل فاتورة: عرض التفاصيل / تعديل (مسودة فقط) / ترحيل / طباعة / حذف (مسودة بلا مدفوعات فقط)

### إنشاء فاتورة جديدة

**نموذج ثلاثي الأقسام** (Modal 3xl):

#### القسم 1 — بيانات رأس الفاتورة (شبكة أعلى)
| الحقل | ملاحظات |
|---|---|
| **العميل** (إلزامي) | حقل ذكي يعرض الرصيد والهاتف |
| تاريخ الفاتورة / تاريخ الاستحقاق | الاستحقاق يحرّك أعمار الديون |
| **نوع الدفع** | ⭐ **نقدي** أو **آجل** — يحدد القيد (انظر أدناه) |
| العملة + سعر الصرف | YER افتراضياً — عملة أخرى تعرض «المعادل بالأساسية» حياً |
| **الخزينة** | إلزامية للنقدي — قيد النقدية يقع على حسابها |

#### القسم 2 — السلع (المحور الأكبر)
جدول سطور قابل للتمرير:
| العمود | الوصف |
|---|---|
| **المنتج** | حقل ذكي بشارات: السعر، الباركود، الوحدة — الاختيار **يعبئ السعر تلقائياً** من سعر البيع |
| الكمية | تُضرب في السعر |
| سعر الوحدة | تعبئة تلقائية تُحترم تعديلك اليدوي |
| **خصم السطر %** | يظهر فقط إذا «إظهار الخصم» مفعل بالإعدادات |
| الإجمالي | كمية × سعر × (1 − خصم٪) |

زر «إضافة سطر» + حذف أي سطر — **عداد أصناف حي** في رأس القسم.

#### القسم 3 — الملاحظات والمرفقات والملخص
- **خصم الفاتورة**: نوع (نسبة % أو مبلغ) وقيمة — يظهر تحت المجموع الفرعي (إن كانت مفعلة)
- **الملخص الحي**: المجموع الفرعي → خصم الفاتورة → صافي → **الضريبة** (نسبة VAT من إعدادات الشركة، بشارة %) → **الإجمالي**
- الملاحظات + **المرفقات** (حتى 2MB للملف: صور/PDF — تُحفظ مع الفاتورة وتُحمّل من التفاصيل)

### حساب المبالغ (المنطق المحاسبي)
```
المجموع الفرعي   = Σ (كمية × سعر × (1 − خصم السطر٪))
خصم الفاتورة     = min(نسبة٪ × المجموع الفرعي أو مبلغ, المجموع الفرعي)
صافي بعد الخصم  = المجموع الفرعي − خصم الفاتورة
الضريبة          = صافي بعد الخصم × vatRate%    (0 إن كانت مخفية)
الإجمالي         = صافي بعد الخصم + الضريبة
```

### ترحيل الفاتورة — نقدي مقابل آجل

| | **فاتورة نقدي** | **فاتورة آجل** |
|---|---|---|
| **القيد** | مدين **حساب الخزينة** / دائن المبيعات + VAT | مدين **العملاء (المدينون)** / دائن المبيعات + VAT |
| **الحالة بعد الترحيل** | `paid` (مدفوعة) مباشرة | `posted` |
| **رصيد العميل** | لا يتأثر | يزيد بالمستحق |
| **المخزون** | حركة `out` لكل صنف | نفس الشيء |
| **التحصيل لاحقاً** | غير مطلوب | بسند قبض يطبّق على الفاتورة |

> ⭐ **الفاتورة النقدي صادقة في كل السجلات**: `paid_amount = total` و `status = paid` في نفس اللحظة — لا انفصال بين السجل والقيد.

### دورة حياة الفاتورة
```
مسودة (draft) ──ترحيل──▶ مرحّلة (posted) ──سند قبض──▶ مدفوعة جزئياً/مدفوعة
                                    └─────── إلغاء ──▶ ملغاة
```

### الحمايات المالية
| المحاولة | النتيجة |
|---|---|
| حذف فاتورة مرحّلة | ❌ ممنوع |
| حذف مسودة عليها مدفوعات | ❌ ممنوع |
| تعديل أسطور فاتورة مرحّلة | ❌ ممنوع |
| إنشاء فاتورة بـ paidAmount > totalAmount | ❌ ممنوع |
| تكرار نفس الفاتورة (نفس الطرف/التاريخ/السطور) | ⚠️ حوار بصمة المستند |

### تفاصيل الفاتورة وطباعتها
بطاقة التفاصيل تعرض الرأس + جدول السطور (بالكود والباركود والوحدة) + المرفقات + أزرار **طباعة** (تصميم عالمي: رأس متدرج، ملخص بخصم وضريبة بشارة، مبلغ بالحروف) و**تصدير Excel**.

## العملاء

**المسار**: `/sales/customers`

### قائمة العملاء
- بحث نصي (الاسم/الكود/الهاتف) من الخادم + فلتر نشط
- الأعمدة: الكود (`CUS-00001`)، الاسم، الهاتف، **الرصيد**، حد الائتمان، الحالة

### بطاقة العميل
- **الرصيد الرئيسي = صافي** (ما يستحق عليك) + تفصيل تحته: مدين بالكهرماني / دائن بالزمردي
- **الرصيد الافتتاحي** بسطر منفصل تحت الرصيد
- سجل كامل عبر **كشف حساب العميل**

### إنشاء/تعديل عميل
| الحقل | ملاحظات |
|---|---|
| الكود | `CUS-00001` تلقائي |
| **الاسم** (إلزامي) | حوار التكرار يفحصه |
| الهاتف/البريد/العنوان/الرقم الضريبي | تظهر في الفاتورة المطبوعة |
| **حد الائتمان** | مرجعي للتحكم في البيع الآجل |
| **الرصيد الافتتاحي + تاريخه** | ⭐ يرحّل كقيد افتتاحي — يظهر كسطر «رصيد افتتاحي» في الكشف ويقع في أعمار +90 إن كان غير مؤرخ |

> 🔒 حذف عميل له فواتير **ممنوع** (رسالة واضحة) — عطّله بدلاً من ذلك.

## عروض الأسعار

**المسار**: `/sales/quotations`

### سير العمل
```
عرض سعر (QOT-NNNN) ──قبول من العميل──▶ تحويل لفاتورة ──▶ دورة الفاتورة
```

1. **إنشاء عرض**: نفس نموذج الفاتورة (عميل، سلع، أسعار) + **تاريخ انتهاء الصلاحية**
2. الحالات: `draft` → `accepted` (عند الموافقة) / `rejected`
3. **«تحويل لفاتورة»**: ينسخ السطور لفاتورة مبيعات جديدة كاملة — العرض يصبح `converted` (محروس من الحذف)

## مردودات المبيعات

**المسار**: `/sales/returns`

### إنشاء مردود
1. اختر **العميل** ثم **الفاتورة الأصلية** من قائمة ذكية (تعرض فواتيره المرحّلة فقط، مع سطورها جاهزة للاختيار)
2. حدد الأصناف والكميات المرتجعة + **سبب الإرجاع** (إلزامي)
3. الرقم `SRT-NNNN` تلقائي

### الترحيل — أثر ثلاثي
```
مدين المبيعات (أو مردودات البيع) / دائن العميل
+ حركة مخزون in (العودة للمستودع)
+ رصيد العميل ينقص بمبلغ المردود
```

> المردود المرحّل محمي من الحذف والتعديل مثل الفاتورة.

## الدفعات والتحصيل (تكامل مع السندات)

التحصيل يتم من **الحسابات ← سندات القبض** — انظر [دليل الحسابات](01-accounting.md):

1. سند قبض ← اختر العميل
2. **«تطبيق على فاتورة»** يعرض كل فواتيره المستحقة
3. ترحيل السند = خصم الفاتورة + تحديث حالتها + قيد الصندوق — **ذرّي**

## تدفقات سريعة

| أفعل | الخطوات |
|---|---|
| بعت نقداً واستلمت فوراً | فاتورة جديدة ← نوع الدفع **نقدي** + خزينة ← ترحيل (تنتهي القصة) |
| بعت آجلاً | فاتورة **آجل** ← ترحيل ← التحصيل لاحقاً بسند قبض |
| أصدرت عرض سعر | عروض الأسعار ← جديد ← عند القبول «تحويل لفاتورة» |
| عميل أرجع بضاعة | مردودات ← اختر الفاتورة ← حدد الأصناف ← ترحيل |
| أعرف متى تستحق أموالي | التقارير ← كشف حساب العميل / أعمار الذمم |
| منع تفلات اسم مكرر | حوار التكرار يفحص تلقائياً عند الإنشاء |
